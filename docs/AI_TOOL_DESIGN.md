# AI 工具设计与错误恢复规范

状态：开发规范。适用于 PC 与 Android 共用的模型工具、能力发现、参数校验、结果续读及相关回归。建立于 2026-11-17。

新增或修改工具前先读本文，再核对仓库精确锁定的 DSH 源码及领域合同。本文规定设计和验收方法，不替代运行时接口，也不把尚未完成的方案当作实现。

## 本次问题与判断边界

一次创作会话中，18 次创作能力调用均未进入业务执行：16 次混用普通调用与结果续读，另 2 次遗漏业务参数对象。模型反复查询能力目录，却未取得具体操作的参数结构，也没有调用创建角色操作。模型确实生成了错误参数；接口发现流程、调用形式和纠错反馈也增加了误用与重复失败的机会。

这不能证明全部业务能力失效，也不能证明全部数据校验过严。排查应分别记录：模型实际收到的合同、生成的原始参数、解析与分发参数、失败阶段、业务是否开始执行、持久化是否提交。请求日志中的内部声明不等于服务商实际收到的最终 HTTP 请求；未核对适配链时不得宣称服务商完整接收了 Schema。

本次 Android 沙箱问题不属于本轮修复范围。复盘只保留上述匿名机制与计数，不复制用户原始会话、凭据、真实角色或聊天正文。

## 设计原则

设定工具执行 EJS 控制器时，使用正式 EJS 包编译模板，不维护手写标签解析器；设定输出保持文字语义，`locals` 与 `this` 绑定本次上下文。`_` 直接绑定声明在该 Host 包依赖中的完整 Lodash，深拷贝、对象映射及链式调用保持库的正式语义；不维护只实现少量方法的同名替代品。聊天读取函数从本会话已有的角色聊天历史返回文字，不追加数量上限，也不修改消息；`getvar` 的 `clone: true` 必须返回独立副本。条目执行失败仍沿原有逐项错误合同返回。

`getwi` 按标题或完整路径取用当前聊天设定库中的正文，规则开启、关闭和关键词是否命中均不影响点名引用。普通文字原样返回，EJS 在同一份聊天上下文中递归处理完整正文。找不到目标或匹配多个目标时报告错误，循环按当前调用分支检测并报告完整路径链。

设定库和角色扮演预设中，关闭触发规则后，正文留作引用素材。其他模板通过 `getwi` 取用时才执行被引用的 EJS，输出交回引用方，随引用方的规则进入请求或工具结果。v19 将以前独立保存的 EJS 引用设定转换为规则关闭的普通条目，保留原正文格式和源码。

指定位置的 EJS 渲染失败时，记录带码诊断，该条跳过本次插入，其余设定和用户消息继续组装。经过设定读取工具的 EJS 失败沿用逐条错误回执。

### 让正确调用容易构造

- 工具名、字段名、说明与执行语义一致。明确区分能力组、操作编号、对象编号、范围及结果文件；目录中的 `target` 是目标种类元数据，不是 `character_id`。
- 参数结构表达实际可用形式。当前 DSH 或服务商不能表达的跨字段关系，必须在工具说明、发现结果与可恢复校验中明确说明，不能只藏在执行分支里，也不能宣称已由 Schema 强制表达。
- 已知的当前预设、会话及默认编辑角色由 Host 按原合同解析；不要求模型重新编造。显式指定其他角色仍使用发现所得的准确 ID。
- 能力发现按组渐进加载。请求某组时默认给出该组完整操作参数；可指定具体操作缩小范围，或明确要求只看摘要。不要额外要求模型记住一个开关才能取得准确参数，也不要常驻注入所有组的完整 Schema。
- 示例展示真实可接受的调用形式。没有业务必填字段的读取可以展示空参数；需要真实对象 ID 或业务正文时给出准确 Schema 和发现方法，不把占位编号伪装成可执行示例。
- 按需加载领域知识与实时参数各有用途。技能不能代替参数合同，参数合同也不承载整套长教程。

「隐藏工具调用过程」在角色预设中常驻。`<roleplay_output_protocol>` 开头要求通过 `eleckoi_roleplay_reply` 提交扮演正文，禁止绕过工具直接输出角色回复。设定库和变量工具的 Schema 说明开头提醒模型查看该协议，按本轮情况判断是否调用回复工具。工具结果数据与历史记录按原合同保存。工具按角色声明外层字符串字段，字段名关联发言角色，字段值是完整正文。单人填写一个角色字段，多人按发言顺序填写各自的字段。角色和顺序由剧情与设定决定。Client 用 DSH 工具参数流按到达顺序显示头像和正文，历史从原工具调用读取正文。普通助手文本保留在 DSH 轨迹。成功的回复调用使用 DSH 的工具完成接口结束轮次。没有可选登场角色时，卡片封面名称用作发言名称。

回复工具说明列出当前可发言的全部角色，名单和参数由同一份角色字段定义生成。模型填写本轮发言角色对应的字段，字段值直接填写台词、动作或叙述。发给模型的聊天历史在单角色场景直接使用正文，多角色场景把发言者放在单独一行。正文保留作者或模型原本填写的文字。

子代理通过同一个工具提交的正文实时显示在主对话中。工具成功后，主代理收到已显示的正文，计入本轮调用要求。普通分析结果沿用默认回复步骤。

### 校验保护数据，不增加机械负担

| 情况 | 处理原则 |
| --- | --- |
| 只读操作省略业务参数对象 | 明确定义为提交空对象，仍通过该操作原有参数校验；有必填字段时仍报准确错误 |
| 显式 `null`、错误类型或未知字段 | 按正式合同报告，不猜测含义或静默丢弃 |
| 写操作遗漏参数 | 不自动补齐业务内容；返回该操作的准确合同 |
| 普通调用与续读混用 | 不擅自选择其中一种，不执行业务操作；说明冲突与各自合法形式 |
| 角色归属、会话权限、路径授权、版本冲突 | 保留正式检查，失败时说明真实原因与恢复方法 |
| 写入超时、回执丢失或提交状态不明 | 先通过领域读取核对实际状态，不自动重复写入，不宣称未执行 |

默认值只沿明确合同使用。禁止自动猜 ID、挑首个对象、跨范围替换、吞掉异常、用空结果冒充成功，或为减少失败擅自放宽数据归属和冲突检查。

不添加未经用户要求的条目数、正文长度、搜索命中、批量数、读取总量或执行次数上限。性能优先通过算法、索引、分页、流式读取与资源释放解决。分页必须能取回全部有效结果。

### 错误应帮助恢复

- 保留原失败码、诊断、官方错误状态与日志，不另建失败类型或把失败改成成功。
- 在错误内容旁提供当前工具的合法调用形式；已识别具体操作时提供该操作的准确参数合同，能够确定合法空参读取时附最小调用示例。
- 区分输入未通过、执行失败、提交状态不明。只有确定尚未进入业务执行时才写“未执行”；不得对全部失败统一承诺未产生影响。
- 恢复说明必须可操作：缺哪个字段、从何处取得准确 ID／路径、如何重新读取版本或查询状态。避免只重复禁止事项、抛堆栈或要求重新加载整套技能。
- 不根据错误文本相似性自动改参、切换目标或重试写入。错误恢复由模型依据真实合同作出；程序只执行用户已授权且语义明确的操作。

## 现有创作工具合同

保持现有三个工具及原权限组，不新增独立通用结果读取工具。

1. `eleckoi_list_toolsets`：列出能力组与简短用途。
2. `eleckoi_describe_toolset`：`toolset_id` 指定能力组，默认返回操作的 `inputSchema`；`operation_ids` 可缩小范围，`include_schema: false` 明确选择摘要。
3. `eleckoi_call_capability`：普通操作使用 `capability_id`、`arguments` 和可选真实 `character_id`；只读操作省略 `arguments` 等同空对象，写操作须明确提供。续读只提供 `result`，路径来自本会话已有溢出回执，不能编造。

普通读取示例：

```json
{"capability_id":"presetPrompts.glob","arguments":{}}
```

省略空参数的同义读取：

```json
{"capability_id":"presetPrompts.glob"}
```

续读继续附在各领域现有入口，沿准确 `next_offset` 直到结束；搜索和续读不重新执行业务写入。所有权、跨会话、文件有效性及 UTF-8 边界检查沿原结果存储合同处理。

当前 `defineTool` 是隐式对象根参数 DSL，普通调用与续读的跨字段互斥仍由说明及执行前检查表达；不能将其描述为已用根联合 Schema 强制约束。未来改变调用结构，应核对 DSH、服务商及历史呈现合同，验证收益后整体替换，不新增长期双轨格式。

## 模型生成约束与服务商差异

服务商的 `strict` 限制模型生成的参数结构，程序的运行期校验保护实际数据；二者各有作用。结构正确不等于对象、范围或业务意图正确。

开启 `strict`、改变 `oneOf`／`anyOf`、空值及必填投影前，核对实际模型路由、适配器序列化、服务商与精确 Schema 子集；不得仅根据模型显示名称判断能力。当前通用自由业务参数对象也不能直接视作符合各服务商严格模式要求。本轮不更改服务商配置或开启严格模式。

## 验收与持续改动

- 保留成功路径：发现操作、读取必需资料、创建／修改合成角色、读取核对、持久化冷恢复。检查最终领域结果，不只断言调用了某个函数。
- 保留失败路径：错误类型、未知操作、必填缺失、混合续读、错误角色、跨会话、版本冲突和取消；不得为消灭报错而放宽业务断言。
- 增加恢复路径：从本次错误参数出发，经模型实际可见的错误合同构造正确调用，再完成原任务。固定响应适配器能验证请求与执行链，不能据此宣称真实模型已学会或某服务商成功率提高。
- 涉及大结果时，使用大量合成条目、长正文及末尾关键词，覆盖完整续读、全部命中、正式 Host 输出策略、保存预设恢复与模型请求组装。检查原错误内容及恢复合同均能进入下一次请求。
- 真实模型评估另外记录任务完成率、首次调用有效率、错误恢复率、重复失败、误写与上下文开销。允许多种正确路径，不按固定顺序、措辞或无关格式否决正确结果；真实评估结论须对应实际运行证据。
- 本地只运行与改动相关的检查，不用无关或未进入包的测试阻塞已授权发布；发布先出包与后续独立测试沿既有发布规范。
- 每次修改注明已实现、未解决及验证边界，不把源码检查、合成适配器或浏览器夹具当作真实模型、安装包或真机验收。
