# 创作工作室的工具与知识分层

状态：当前实现与维护约定。更新日期：2026-11-13。

工作室具备编程能力，AI 可以在工作区编写 HTML、JavaScript、CSS 和资源文件，再通过产品能力写入角色卡。程序文件的制作、已登记产品数据的修改和创作知识的加载各有自己的入口。

## 楼层界面的技术职责

常规角色卡保留宿主聊天楼层。正则把稳定标记或有明确边界的文本转换成 HTML，富消息环境负责页面显示与 JavaScript 执行。正文也可以直接包含 HTML；后台脚本可以同时处理变量规则、事件、按钮及脚本面板。页面组织范围、源码位置和加载机制分别判断，不能仅凭弹窗或外部页面文件推断已经替换整套聊天界面。

独立前端项目用于自定义整个聊天内容区的交互结构，沿本项目正式聊天、变量与 SDK 合同运行。它不是常规楼层界面的前置步骤；正则、HTML 与后台脚本也不是互斥路线。

## 四层加载

1. **常驻入口**：简短说明当前角色、能力发现方式和技能路由；默认不放完整 SDK、教程或所有领域参数。
2. **任务技能**：正式 DSH `skill` 工具按名称加载 `SKILL.md`。角色配置及脚本、资产、常规楼层界面、独立前端项目分别有技能。
3. **专题参考**：技能正文按任务指向 `references/*.md`；文件读取工具读取实际随包文件。SDK 方法、EJS 阶段、资产打包各自按需展开。
4. **实时操作合同**：`eleckoi_list_toolsets` 查能力组；`eleckoi_describe_toolset` 指定 operation_ids、include_schema 查询准确参数；`eleckoi_call_capability` 执行。

技能知识说明“如何选择和完成任务”，运行 schema 说明“当前这项调用接受什么参数”。二者分别维护，不把长教程塞进函数描述，也不把文档中的示例编号当真实对象。

`guides.ts` 仅保留短路由和必要的操作提示。完整领域说明维护在 [角色配置参考](plugins/authoring-configurations.md)、[资产创作](plugins/character-assets.md)、[界面创作](plugins/character-frontends.md) 和 [作者 SDK](plugins/author-sdk.md)。

## 随包与更新

四个角色创作技能放在 `packages/client/features/dsh-client-shell/skills/`。现有 `@eleckoi/dsh-runtime` 已通过正式 `dsh-skill-filesystem` provider 注册此根目录，因此不新增技能协议或第二个文档读取工具。

`pnpm generate:plugin-docs` 将维护文档同步到对应技能的 references；`pnpm check:plugin-docs` 校验来源与副本。技能主体保持短小，参考文件必须一并分发。安装版通过 Host 文件读取工具访问随包路径，不能要求用户工作区含有 ElecKoi 源码，也不能用 shell 假定 app.asar 是普通目录。

已有创作预设不因知识更新被重写；当前运行指引及技能目录直接提供新入口。模型是否主动读取取决于任务匹配和实际调用，不能把“已登记技能”描述为“AI 已读完参考”。

## 写入与范围

角色配置从工作室当前角色绑定取目标；共享全局配置使用明确 target。资产和独立项目前端只操作当前角色。普通数据与版本冲突沿现有合同处理，工作区文件不直接改产品数据库、内部目录或客户端 DOM。

资产导入通过正式 DSH 文件服务解析工作区源文件，按字节窗口读取后进入现有资产发布流程；复制引用返回 `asset://UUID`。已有编辑器订阅收到原来的目录失效通知，不另存第二份编辑状态。前端源码批量写入进入现有项目事务，未提交文件保留。

常规创作保留聊天楼层，通常由显示正则将标记或文本区块替换为 HTML，再由富消息环境显示和运行；正文也可直接包含 HTML。后台脚本可以同时提供变量规则、事件、按钮和弹窗。页面组织范围、源码位置和加载机制分别判断，脚本有界面或页面资源来自外部文件，都不表示应切换到独立项目。

独立项目只用于任务或现有工程需要自定义整套聊天内容区交互的情况，例如接入 AI 的网页游戏或模拟系统。项目可以使用自己的控件通过 SDK 直接发送操作，当前仍保留宿主输入框和应用外壳。资产库是共用的资源所有者。具体边界和工作流见 [界面创作](plugins/character-frontends.md)。
