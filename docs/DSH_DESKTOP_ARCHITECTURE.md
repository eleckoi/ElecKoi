# ElecKoi 的 DSH 官方客户端架构基准

状态：当前架构目标。本文记录 ElecKoi 如何对照官方源码；**DSH 官方客户端及其同版本源码是唯一架构基准**，本文不另立一套与其平行的客户端标准。决策见 [ADR 0012](adr/0012-dsh-official-client-baseline.md)。

消息目录在 PC 和安卓共用已有 TanStack Virtual，只挂载可见项与前后三项，按稳定会话 ID 测量，不截断目录；手机仍沿原滚动位置和侧滑操作。小头像通过原本地媒体入口请求 256／512 像素派生图，浏览器选择显示密度，预览、编辑、导出及持久化引用继续使用原图。共用 product-data 媒体实现以锁定 sharp 生成无损 WebP，保持比例、透明、动画和方向；PC 原协议与安卓原认证 Host 共用该实现及内容寻址的私有浏览器缓存。派生图属于可丢弃显示缓存，放在原 owner／slot 的独立子目录，原媒体及数据库写入仍归 Host；替换提交、清空、回滚和删除同步清理，启动后台清除中断文件及孤儿缓存，不阻塞首屏、不持有原图文件句柄。Android 生产依赖暂存必须包含 Linux ARM64 glibc 的 sharp 与 libvips，缺失即报错，不能只因 Windows 解码成功就宣称安卓运行通过。

## 权威来源

角色瀑布流在 PC 管理器与安卓角色页共用 `VirtualMasonry`，沿现有 TanStack Virtual 的 lanes／measureElement／takeSnapshot 接入，仅挂载视口附近卡片并共用测量观察器，列数、间距、封面比例和卡片外观取现有 CSS。原完整目录继续负责搜索、排序、分组与批量操作，虚拟化不截断数据或将“全选”缩成已挂载节点。安卓从列表进入角色详情时，React Activity 隐藏原瀑布流并保留分列，返回以点击时的卡片 ID 和相对视口位置恢复。返回后的异步补测只按该卡同列上方的高度变化补偿滚动，用户继续操作列表时恢复 TanStack 原滚动补偿。完整离开角色列表时仍通过页面 scrollPositions 保存测量与锚点。大封面沿原媒体入口和同一缩略图生命周期按实际显示长边选择 256／512／1024／2048，超过对应分辨率用原图，原图查看、编辑和导出保持。没有新增跨端通道、数据库字段或第二份角色目录。

PC 预设主页面只展示原预设目录、资料、使用说明与更新时间线；编辑复用既有受管 Electron `child` 窗口和稳定 frameName，独立窗口按明确预设 ID 与白名单分类启动，和角色卡编辑器共用呈现骨架。跨窗更新继续走原 `eleckoiPresets` 目录与详情订阅，保存、外部冲突及正则／脚本各自的作用域和版本模型保持，不引入浏览器内存广播、产品 IPC、数据库副本或迁移。工具配置在该编辑器右侧内联原组件，工具成员草稿及正式工具配置服务边界不变。基础资料合并后，`eleckoi.preset.editor.profile` 与 `eleckoi.preset.editor.introduction` 两个原扩展座位继续分别接入。

展示页直接使用 `AgentPresetCatalog.presets` 已包含的完整 `profile`、名称和模型标签，不再读取或订阅完整编辑文档。已就绪目录的当前选择在首帧初始化，后台目录刷新不清空展示；外部保存沿原目录订阅刷新资料。提示词、正则、脚本及版本正文仍仅在原编辑流程读取，不新增展示缓存或以延时掩盖空白。

编辑器的官方插件配置链接按 [ADR 0043](adr/0043-editor-main-window-plugin-navigation.md) 交给现有主窗口：原生壳只转交明确入口并复用主窗口聚焦，主窗口的原 Client 插件导航打开网页搜索或子智能体配置。回执严格绑定目标窗口与顶层 frame，错误回传原入口；独立预设编辑区保持当前工具详情。此平台例外不携带产品数据或配置值，设置仍通过官方 Remote 读写，上游提供对应受管跨窗入口后整体退役。

预设新建以正式创建接口成功为提交边界：从其返回的完整预设提取原目录摘要字段发布到已就绪目录，立即选中，再后台刷新权威目录；不在页面再次等待目录往返。变更通知只刷新仍被详情订阅者使用的完整文档，不遍历重读所有访问过的预设。侧栏删除先经过现有确认弹窗，明确显示目标名称；取消不写入，失败保留目标及错误可重试，成功后采用删除接口返回的目录。目录和详情继续使用原服务、订阅及修订顺序，没有新缓存或跨端合同。

PC 预设说明与更新记录的编辑复用公开 `EditorWritingBoard`，同角色卡正文共用 CodeMirror 视口、完整草稿及单实例沉浸；原说明／记录的保存、取消和记录身份保持。短只读文字保留原段落排版，超过 12000 字符或达到 200 个换行时改用完整只读视口，接近可见区后才挂载，阈值仅决定呈现方式，不截断内容或限制保存。预设提示词、正则匹配／替换及脚本源码／信息／设置继续复用原工作台控件；切换视图卸载隐藏编辑器，不执行说明中的代码。手机紧凑装配维持原输入与段落行为。

变量配置由角色素材库独占保存；编辑器的当前版本只表示编辑对象，开场白只提供新建会话的初始关联，之后可在当前会话的「变量查看与管理」选择或取消关联；未关联的旧会话也可直接选用本角色版本。变量工具每次调用经 `readConversationVariableContext` 读取该版本的最新目录、类型、默认值、说明、规则和校验，本轮上下文仅保存候选值，不持有生产配置副本。`defaultStateJson` 属于实时配置，聊天开局及楼层快照只用于初始记录、回看和回退。新增定义可读取默认值，未存储的当前值明确为缺失；不自动复活工具已删除的字段。补丁提交前同时核对共享候选值和最新配置，修改期间发生变化则返回可重试冲突，不覆盖新状态。关联版本缺失不阻断聊天或导入，不自动改用编辑器选中的其他版本，已有值和历史保留；恢复相同版本编号后重新使用其最新配置。

当前仓库锁定 `deepseek-ai/deepseek-harness` `0.2.2-rc.3`，提交 `38a6a5c965aa99ab525161efb7cc5cf1fe62fced`。核对架构和行为时使用这个**精确提交**的官方源码，而不是浮动的 `master`、旧版文档或 ElecKoi 的临时实现：

变量存档同时保存值和来源身份：作者定义引用版本编号、条目编号及所属容器，运行时新增项保存自己的稳定身份与容器归属。工具目录由最新定义及当前状态中有明确运行时来源的项组成；不比较旧配置、不扫描未归属旧值补目录，也不保存删除黑名单。同一身份改名保留值，新身份同名不继承旧值；删除定义不清洗历史。值与身份一起提交、快照及回退，不将配置正文、规则或默认值复制进聊天。schema v17 升级及旧聊天归档 v1/v2 导入只在边界建立一次简单基线：沿会话保存的关联版本识别已声明字段（包括停用项），其他旧字段作为 runtime 保留，不追查历史来源。原始变量值及快照不重建，编辑器选中版本不参与；后续新写入才按明确来源和稳定身份处理。

- [Web Client 架构](https://github.com/deepseek-ai/deepseek-harness/blob/38a6a5c965aa99ab525161efb7cc5cf1fe62fced/docs/subsystems/web-client.zh.md)：Host、Remote、Client model、Slots 与 React。
- [官方 Desktop](https://github.com/deepseek-ai/deepseek-harness/blob/38a6a5c965aa99ab525161efb7cc5cf1fe62fced/apps/desktop/README.zh.md)：Electron 壳、受管 profile、Web Host、客户端资源及插件管理。

升级时先锁定同一上游发布批次的提交、包和构建产物，再把上述引用与本仓库的依赖一起更新。不同版本的官方文件不能混作一次架构依据。

产品组合在官方 `system-prompt` 配置中显式设置 `includeHarnessIdentity: false`，关闭上游默认开启的固定 Harness 身份介绍；部署 `personaPrefix` 默认留空，不再声明模型名为 ElecKoi。桌面 Agent 组合与 SDK 兼容组合保持一致，SDK 仍接受明确的 `DSH_SYSTEM_PROMPT` 自定义值。该调整仅使用官方配置项，保留各工具、功能插件和预设自己的提示词注册，不修改 DSH 源码或增加依赖补丁。

预设的常驻系统指令通过官方 `system-prompt/assemble` 进入 `sections` 首位，使用 `interpolate: false` 保留产品已经处理的文字和字面量模板标记；角色聊天与创作工作室都在官方循环记录 `system/message` 前完成组装。官方工具与环境说明随后保留。不得在 `llm/stream` 再重复追加常驻系统指令，否则实际请求与轨迹的初始／更新系统提示词会分离。请求预览重新组装当前系统提示词，不将历史系统提示词与当前预设再次拼接，也不改写旧轨迹。

创作预设提示词只使用文字常驻与 Agent 读取的必读／选读，目录继续由产品预设条目及分组提供，不映射工作区磁盘文件。预设编辑器对创作用途不显示关键词、EJS 或引用入口；角色扮演仍保留这些能力。工作室通过原有创作能力三工具发现和调用 `presetPrompts.glob/grep/read`，读取当前 Session 正式绑定的预设，不要求选择编辑角色，也不启用角色设定库／剧情变量工具。虚拟路径算法与角色设定读取共用；必读正文沿既有前置注入进入请求，读取回执核对实际发送时的编号、标题和正文。当前内容发生变化时直接返回新正文，避免引用尚未发送的文字。以 Agent 为弱键仅保存最近一次实际发送的库对象，预览组装不更新它，不新增 Session 事件、持久副本或逐轮缓存。目录、搜索和正文结果沿用原创作工具组的溢出保存与 `result` 续读／搜索入口，按 `next_offset` 直到末尾，不新增读取工具、总量或页数上限。

提示词来源需区分文字所有者与组合启用者：`web_search`／`web_fetch` 的外部内容说明来自官方 `dsh-tool-web`；文件交付与路径链接说明来自官方 `dsh-deliverable-file-references`；DSH 源码目录、Web GUI 和 HMR 说明来自官方 `dsh-harness-dev-context`。后两者由官方 Web App 组合登记，联网工具由产品预设能力组装配。产品自己的预设常驻正文、角色指令、自动配图协议和工作室编辑目标由对应产品插件贡献。更改顺序不删除这些官方说明，也不表示它们的全部环境描述都适用于每个平台。

创作能力的三种工具通过工作室既有的正式子座位投影接入 `tool.call.toolview`。网页组件按准确工具名及 `capability_id` 显示操作图标、可读结果和逐行替换；目录、正文及修改明细复用共用虚拟列表与官方 DisclosureRow。展示只读取当前调用保存的参数与结果，不按当前产品资料重建旧名称、旧值或执行修改。必读预设提示词保留真实读取回执，结果续读只显示本次片段与偏移；未知结构、溢出引用和附件保留原生展示及查看原始调用入口。无新增 Session 事件、数据库字段、持久缓存或迁移。

创作工作室侧边栏只投影已有 `eleckoiCreatorStudio` 或 `eleckoi-creator-active` 关联的会话及其子会话；角色目录中的会话与后代始终排除。分组、未分组、搜索及行操作使用同一呈现范围，切回原生工作区时使用该页面原有范围。筛选随官方面板和目录订阅更新，不转换会话、重选预设或改写工作区成员。两类产品聊天继续使用同版官方输入框和原有自定义菜单；手机不再通过全局按钮最小高度覆盖官方控件，工作室正文留白只由官方 Chat 提供。模型参数沿官方菜单材质和紧凑字段尺寸展开，面板内滚动保留全部字段。

角色和创作的输入菜单共用 RoleplayInputMenu，首页直达预设切换，角色扮演另外提供全局设定库，创作工作室不提供该入口；变量、请求预览和注册脚本位于「更多」。预设直接订阅现有 PresetCatalog 并调用 setActive，按 purpose 隔离；全局库复用现有 CharacterConfigurationModel、revision 与草稿钩子，仅修改 enabled，确认保存后写入，离开前检查草稿。入口与所选会话一起卸载，后台完成不重开另一会话的菜单。菜单定位、Portal、焦点和键盘沿官方 Menu，主菜单全部展示且不按聊天区限高滚动；只有大量脚本列表独立滚动。共用官方 Modal 管理选择弹窗的焦点，overlay Back 优先关闭上层；不增加 Remote、协议或持久缓存。

安卓工作室的工作详情默认与桌面一致为「标准」。移动 bundle 通过官方 `ui-chat.config.transcriptView` 提供该默认值；安卓页面未开放工作详情档位切换入口，本次不新增该入口，不修改官方展开与收起逻辑。

角色消息与楼层按官方 Chat 节点的显示顺序投影，事件序号继续作为原消息的操作地址。处理过程节点的锚点可能早于其用户输入，不能再按锚点排序后编号。删除回复或重新生成保留输入时，使用官方闭合事件补齐边界，并将结束原因标为 `aborted / user`；`interrupted` 继续表示真实异常中断，保留其错误展示。此处不新增 Session 格式、迁移或历史记录改写。

角色流式消息沿用同版官方不可变 Chat 节点与 keyed renderer。产品映射按原消息对象复用，配对按会话／Session／正式消息或节点身份索引，未变化的消息、处理记录和输入图片保持引用；正文、显示规则、状态、变量、附件等字段实际变化时正常替换。原生输入到持久消息继续按 requestId 交接，不按相同文字猜测身份。行座位按同一不可变消息数组建立一次索引，全部 WeakMap 仅保存挂载数据的派生映射，不写入 Session、数据库或浏览器存储，也不截断历史。一次官方通知中的正文与运行状态沿既有 publishOfficialState 同步发布，完成、取消和失败保持相应终态。正文继续用官方 MarkdownText 的增量段落及原滚动控制；产品引号着色仅更新发生变化的文本节点，下划线复用边界相同的 Range，无下划线时不扫描该层全文，卸载时释放观察器与本消息的高亮。

## 文件上传与读取

基础读取随预设详情的 `basicToolGroups` 运行时元数据公布，在预设工具页、管理窗口和对话工具列表中可查看 `read`／`read_image`。该字段不进入预设保存原稿，不提供会改变工作区开关的伪控制。创作预设的界面与执行组合均排除剧情变量、角色设定库和角色扮演计划；保留旧保存值但不让无效选项阻塞工作室。

角色预设开启“创作能力”时直接挂载与工作室共用的创作工具插件，只贡献工具和指引，不接入工作室请求投影、不追加工作室标记。`character.list` 发现角色，`eleckoi_call_capability.character_id` 可明确本次编辑目标，省略才使用当前角色快捷定位；不以界面绑定作为发现、新建或全局操作的前提，显式目标不修改当前聊天的角色归属。

PC 选文件／拖入文件沿同版官方 InputBar：普通文件可取得本机路径时生成文件引用，图片走原生图片附件；安卓系统选择器授权文件内容后，浏览器走同一官方上传、回执和附件存储。原文件不必放进工作区，安卓也不把 content URI 当作 Host 文件系统路径。两端不另写一套上传或文件读取实现。

产品预设直接装配官方 `dsh-tool-fs` 的 `read`／`read_image`，角色和工作室均保留读取。工作区关闭时 `write`／`edit`／`apply_patch` 和命令工具继续关闭；读取按官方文件系统语义工作，不再限于产品自定义的“当前会话附件编号”集合。官方文本读取保留行窗口、字节与单行上限，图片能力依当前模型，PDF／Office 等二进制文档仍需相应官方解析能力，不能把上传成功称为已解析正文。

重复的 `eleckoi_read_uploaded_file`、实现、语言及独立续读归属撤除。旧生成预设在加载边界删除退休插件并补足原生只读组合，不改 Session 历史或用户工具开关；仅在受支持旧生成预设全部更新后，按入口 RETIRE WHEN 删除该边界适配。已有官方文件工具配置保持，不装第二份原生工具。原生 `fs` 权限及路径映射保持，不通过输入框重写路径桥或偷偷移动原文件。

## 角色会话的显示定制边界

角色对话通过显示扩展定制头像、角色正文和特殊工具过程，其余基础机制沿同版本官方实现。此边界适用于 PC、安卓及后续 DSH 升级。

- **显示扩展**：通过官方公开 Slots、节点 renderer 和主题能力呈现角色头像、正文／气泡／楼层、工具过程及已明确的产品入口。已有角色前端、脚本、开场白和重新生成等明确产品功能按原需求保留，不能借对齐删除。
- **官方负责的会话基础**：直接复用 Session 生命周期、Chat 节点与分页、流式通知、草稿／发送／停止、默认视图切换、滚动跟随、输入区装配、弹层定位与官方移动适配。不得因角色外观不同另造一套通用会话行为或滚动骨架。
- **对齐的判据**：不仅检查是否调用官方组件或 API，还须对照锁定源码中的外层容器、滚动所有权、输入区位置、插槽作用域和移动断点。官方存在等价公开实现时必须接回并删除被替代实现；现有代码和旧测试不是长期偏离的依据。
- **缺陷修正的边界**：实际复现上游缺陷时保留必要的最小修正，记录触发条件、修正位置、影响和可核验的退役条件。不得把局部问题扩大为自有默认会话机制，也不得仅凭工作室现场正常就断言官方容器在所有条件下正常。

角色 `ChatPanel`、PC 工作室和安卓工作室现在共用实际注册的官方 `ConversationRoot` 与 `conversation.content` 工厂。产品只向同一工厂提供显示视图和输入座位；滚动、宽度、原生输入与 Session 作用域继续由官方拥有。此前三套页面各自的滚动／输入测量和角色宽度控制副本已经撤除。经新旧 Chromium 实际复现的长历史及流式浮层错位，以同版会话补丁统一修正原生输入座位，不在各页面保留三份定位算法；补丁边界及退役条件见下表。

排查移动故障时必须使用正式安卓角色页和 `MobileCreatorStudioPage`／`MobileCreatorStudioConversation`；PC 的 `CreatorStudioConversation` 单独核对。长历史、滚动后和持续流式输出须实际打开菜单／权限／统计核对位置。隔离浏览器结果与手机验收分别记录。

用户要求的特制最左导航、单一自动化入口、角色显示和菜单是保留项；它们不等于必须保留当前自有布局服务。既有角色卡／预设／脚本／变量／正则、同 Session 编辑与重新生成、绘画配置等明确产品功能也不能机械撤除。原始诊断、回环 Host 网络恢复、受支持旧日志升级及协议参数等补丁分别沿原记录和退役条件保留，不能与无必要的独立界面骨架混为一类。

消息、角色、预设和模型等页面对应的列表／管理侧栏也属于明确保留的产品功能。接入官方列容器时仍须由原页面提供原侧栏内容和操作，并逐项验证导航切换、收起重开及切回恢复；只确认最左导航可见不足以验收。

原轨迹运行依赖已清理，相关检查所需库归入根开发依赖，不增加第二套生产轨迹。升级时同时核对真实原生组件、正式平台组合与长参数流式行为；工具最终保存成功不能替代前台状态检查。

## 工作区目录

应用入口位于 `apps/desktop`、`apps/desktop-host`、`apps/web`；公共合同位于 `packages/shared`，现有产品功能插件位于 `packages/client/features`，Host 数据与运行包位于 `packages/host`，Windows 原生源码位于 `native/windows-frame`。后续 Android 工程进入 `apps/android`，使用独立的平台构建和本地数据。目录决策见 [ADR 0028](adr/0028-multi-application-workspace.md) 和 [ADR 0030](adr/0030-package-responsibility-groups.md)。

## 要达到的结构

ElecKoi 的产品网页资源由受管 Host 在 `/eleckoi/assets/` 提供，资源地址经官方 `webserver/index-inject` 进入页面。桌面窗口与浏览器消费同一份注入和构建产物，Electron 只沿既有可信转发访问 Host，不再单独注入产品资源或直接读取这些文件。Android 使用同一资源装配，另外保留自己的 WebView 启动与平台信息。浏览器入口沿用官方网页壳、认证和 Remote；第三方远程插件代理 Host 即可取得产品资源，不另建远程通信协议。

1. Electron 负责官方桌面客户端所需的窗口、可信来源、受限 preload、本机资源、启动、恢复和更新；不另外发明一套与 DSH Web 应用竞争的客户端框架。
2. DSH 运行时通过官方 profile、bundle 和 patch 层装配。Agent、Session、模型、工具和官方插件由同版本 DSH Host 的正式能力负责。ElecKoi 的扩展优先作为独立的 DSH Host/Agent 插件进入该插件树。
3. 主界面使用官方 Web Client 的模块加载、Cordis 生命周期、Remote、Client model、Slots 和 Renderer。ElecKoi 的页面与角色聊天通过公开的客户端插件合同贡献；第三方插件在其声明的正式扩展位上生效。
4. 新增产品能力默认进入同版本 DSH 的 Host/Client 插件体系。每项能力都必须说明所有者、持久数据来源、公开扩展点、卸载行为和升级验证。需要 Electron 原生能力或产品独有持久数据时，先对照官方 Desktop/Host 的归属方式；无法纳入官方合同的例外必须有具体理由、明确边界和 ADR，不得把现有目录当作永久理由。
5. 不把“使用 Cordis”或“安装后出现在插件列表”当作架构对齐的证明。必须验证实际会话、界面、启停卸载、重启恢复及第三方插件效果。

产品页面的 Vite 入口共用官方 Web Client 已注册的 React、React DOM 与 UI Primitives 实例，只生成导出绑定，不再次打包基础控件及其 CSS。插件专用样式保留官方的层叠顺序；返回按钮、组合按钮等控件的尺寸与内边距由同版本官方组件及样式决定。

PC 输入区外侧模型文字入口通过官方 `conversation.input.model.label` 的 `placement: trigger` 复用既有模型图标展示，以所选模型 ID 与已有配置身份选择图形；菜单当前模型及选项不加模型图标。目录名称、官方 Tag 的本地化和第三方标签优先级保持。手机继续由官方输入区隐藏文字入口并显示原有收纳图标，不增加独立模型图标入口。此展示不改变模型路由、能力声明或提供商分组身份，无新增补丁。

角色聊天与创作工作室使用官方 `conversation.input.model` 组件及其目录、Session 选择、推理等级、键盘和手机收纳，不再通过 `modelAccessory` 装配独立模型浮层。图标只通过锁定版本补丁的提供商分组标题座位贡献，模型行保持官方文字标签，不根据模型名称推断提供商图标；参数经同一补丁声明的根菜单子座位接入，编辑只更新草稿，点击官方 Button 的「保存」后才通过现有 Settings 服务串行合并当前模型的参数，「取消」丢弃该模型草稿。停止输入、失焦、折叠与关闭菜单都不写入；直接关闭时草稿保留到同一目录内重新打开，保存失败保留原错误和草稿，可继续编辑或再次保存。保存期间禁用本组字段和按钮以避免重复提交。自定义接口缺少推理能力声明时遵循官方隐藏推理等级的规则，可在参数的模型能力中明确声明档位，保存后由 Host 发布真实推理元数据；不按名称猜测支持档位。未写入草稿仅以目录为弱键在界面内保留，保存成功或取消后释放。没有数据库迁移、Session 事件或第二套模型目录；补丁退役条件见 `pnpm-workspace.yaml`。手机系统返回优先让已聚焦官方菜单处理 Escape，再返回所属页面。

删除提供商配置沿官方设置命名空间的指定路径执行，不改写旧 Session 的模型选择或按目录顺序猜测替代项。同版官方模型目录保留失效选择并标记不可路由，用户仍能打开会话和重新选择；产品预设装配、空会话创建、Agent 恢复及消息删除不能提前解析模型能力而挡住该入口。角色的恢复只读取现有运行配置，模型信息在实际请求准备阶段刷新；工作室在 `agent/prepare-step` 解析当前选择并准备本轮预设。失效模型的生成请求仍明确失败，用户通过官方 `selectModel` 切换后继续原 Session。消息回退需恢复的已保存模型事实通过官方 Agent 模型选择写回，不把恢复旧事实当成一次需要验证路由并保存全局默认的新选择。

工作室首页的默认工作区标题使用官方公开 `@deepseek-ai/dsh-api-workspace-controller/default-workspace` 命名纯函数。该子路径没有运行依赖，不启动或访问 Workspace Controller；Renderer 导入分类只接纳这个精确公开入口，Host 包、Client Controller 及内部路径仍受原边界约束。

Android Host 在已有启动覆盖配置中为官方 `workspace-controller` 指定 `documentsDirectory: workspaceRoot`，使用应用私有运行目录中的工作区根路径。首次默认工作区仍由官方创建为该根下的 `deepseek-harness/default-workspace`，不调用桌面 Linux 的 `xdg-user-dir`。已登记默认工作区继续按官方持久标识恢复，不因新目录配置而重命名、搬迁或重建；目录冲突与写入失败继续沿正式错误返回。这是平台部署配置，不增加目录探测兜底、数据库迁移或依赖补丁。

聊天记录入口使用官方 `IconQueueOutlineRegular`，两种消息布局的「查看过程」使用同一线框眼睛，思考的弹窗行与外部动态状态栏共用同一小灯泡资源。复制、重新生成与三个点保持原有颜色和视觉大小；两种布局不提供朗读按钮。Windows 标题区域的「应用／编辑」使用同提交 `preload-menu.ts` 的按钮、ShadowRoot、选区恢复与键盘行为，挂载到侧栏按钮左侧的标题栏座位。原生弹出菜单沿用官方坐标缩放和编辑按键流程，调用来源限制为主窗口的可信顶层页面；编辑键只发给该窗口或它持有的已聚焦浏览器。关于接回产品页面，检查更新打开官方独立更新文档，退出沿用桌面生命周期。该通道仅承担桌面壳职责，不引入产品数据桥或第二套更新服务；来源、机械抽取及产品接入差异记录在 `apps/desktop/src/main/platform/electron/dsh/provenance.json`，现有 DSH Desktop MIT 许可随包保留。

角色卡编辑器与预设的搜索框、操作按钮直接使用锁定版本 UI Primitives 的 `Input`、`Button`，边框、圆角及交互状态由组件原样式负责。按产品蓝白主题，编辑器和相关弹窗只将官方主按钮填充、悬停和前景三个主题变量映射为官方 DeepSeek 500、600 与白色；搜索框、次级按钮继续使用官方主题，侧边栏新增图标按钮保留原有外观与尺寸。其他产品样式只保留布局与移动触摸空间。前端编辑工作台位于 ShadowRoot，按实际组件类名复用当前文档已加载的组件规则，主题变量从编辑器继承；控件集合不变时不重复读取样式表，卸载时移除该根的样式节点，不另写一份按钮样式。SVG 片段引用在各自的树内解析，因此同一 ShadowRoot 共用一份主文档当前图标资源的投影，跟随官方主题替换和资源挂载／卸载更新，最后一个控件退出后释放观察与投影；不另画图标或绕过主题资源。

插件首页在官方实验性插件分组之后展示「ElecKoi 插件」。产品身份按运行清单声明的完整包名划分，首页固定角色页面、预设、创作工作室、模型选择和联网搜索五项；完整列表沿用官方「更多」、组合包详情与组件配置的导航和卡片。已安装分组仅显示非官方、非产品内置且实际由用户 profile 安装的包，包括安装文件缺失时的诊断项，不按包名前缀判断用户插件归属。此分组由锁定的插件页面补丁实现；官方提供随产品分发的独立分组、固定条目与完整列表导航，并覆盖现有组合声明及开发接口展示后，可移除该补丁，清理条件同列在 `pnpm-workspace.yaml`。

产品壳承接被替换的 `ui-layout` 入口时，其主题 DOM 投影必须与同版本 `theme-presenter.ts` 一致：读取 `ThemeSnapshot.fontSizes` 和 `fontFamilies` 中的 `text / code / terminal`，同步和释放各角色的正式 CSS 变量；不得继续读取旧的单值 `fontSize` 快照字段。全局字体使用官方 `--dsw-font-family`，插件页面与聊天统计保留官方的字体继承和次级字号计算。角色聊天与创作工作室共用这些正式变量，正文默认 14px、代码默认 11px、终端默认 13px；角色聊天不再单独保存、读取正文字号或字重，代码使用官方 Markdown 字体令牌。

PC 原生错误对话框与 Android 原生错误页面提供用户插件恢复入口，独立于无法启动的客户端插件树。壳先停止受管 Host，再调用同版本官方 `sanitizeProfile` 备份当前 profile 的 `cordis.patch.yml`，按各应用的内置组合清单恢复启动，并保留当前启用的官方 `OPTIONAL_BUNDLES`；用户安装的包和产品数据保留。客户端加载失败、Host 失败都必须到达这个原生入口，不能只写日志或要求进入尚未启动的插件中心。

桌面 Web 启动错误在进入官方 `dshDesktopBoot.failed(string)` 前保留原始说明、调用栈、错误码、自有详情、`cause` 与 `AggregateError.errors`。锁定 0.2.2-rc.3 的原入口只传 `Error.message`，对普通对象执行 `String(reason)`，会使详情变成 `[object Object]`；同版 `dsh-web-frontend` 的受管补丁只修正这一转换，不增加桥接方法或改变启动、恢复与插件启停语义。标准错误、跨窗口错误及 DOMException 保留已有的原始调用位置，缺少调用栈时不补造；重复／循环引用通过路径引用表示，诊断正文不截断。补丁在官方入口完整保留这些诊断后退役；升级须以实际发布的前端运行普通对象、标准错误与嵌套失败回归，不能仅验证格式化辅助函数。

Windows 安装器在应用启动前通过独立原生检查恢复随包可执行映像的正常完整性级别，覆盖主程序、锁定 Electron 运行库、卸载与更新辅助程序。检查器从安装器临时目录运行，只处理安装目录内明确列出的文件，拒绝链接文件与链接资源目录；不重设目录访问控制、不修改上级目录或用户数据，也不关闭浏览器沙箱。写入完整性标记所需的临时权限必须恢复，失败阻断安装完成。此修复不改变 DSH 的工作区授权语义，也不能阻止其他程序在安装后再次改写文件安全属性。

Windows 更新控制和 Electron HTTP 空闲超时采用同一锁定提交的官方 Desktop 实现，位于 `apps/desktop/src/main/modules/updates/dsh`；来源、精确提交和机械导入路径变更记录在该目录的 `provenance.json`，MIT 许可证随桌面资源分发。`UpdateService` 连接官方更新协调器、周期检查、稳定版渠道与 Host 任务锁，`DesktopUpdatePrompts` 将官方确认流程装配到 ElecKoi 窗口，GitHub API Provider 只负责本产品发布及附件定位，不另写下载或安装算法。先创建控制器，再配置发布源，确保元数据、增量和完整下载共用官方 HTTP 执行器。下载校验完成才发布就绪状态，用户确认后才交给 NSIS 安装；安装前确认活跃任务、阻止新请求并等待受管 Host 清理及正常退出；失败保留已下载文件并恢复 Host 与页面。正常退出不自动安装。升级 DSH 时一起核对这些源码、依赖、来源记录及真实 Electron 网络回归。

## 当前代码与目标的差距

以下是**现状记录，不是新的永久架构规定**：

| 现状 | 与官方基准的关系 | 后续核对 |
| --- | --- | --- |
| `apps/desktop-host` 启动同一个 DSH Web Host，并经官方 SessionController 驱动角色会话 | 已采用官方运行路径 | 按精确版本验证会话和插件生命周期 |
| `@eleckoi/dsh-product-data` 在 DSH Host 打开产品数据库、执行迁移并持有全部领域 Repository | 产品 Client 调用全部使用生成的 Typert Remote；数据库唯一写入权、迁移链与媒体写入均已移交 Host | 保持 Host 单一所有权，禁止把 Repository、迁移或第二套跨端业务协议放回 Main |
| `@eleckoi/dsh-client-*` 在官方 Web Client 运行代内贡献界面和受控产品接入点 | 已使用官方 Client model、Slots、Renderer 与 Session 作用域 | 按公开类型和安装探针持续验证第三方插件行为 |
| `patches/` 对锁定官方包进行最小适配；预设桥接通过官方 `agent/created` 生命周期装配顶层 Session 作用域，在模型与工具捕获前准备本轮预设，沿官方 `modelSelection` 日志投影保留每个 Session 的模型，不用全局默认覆盖已有选择；`agent/request` 仅调整本会话输出控制；子 Agent 模型只由 DSH 官方子智能体设置决定；Session 信息性记录补丁见 ADR 0019 | 与上游实现紧耦合，补丁清单以 `pnpm-workspace.yaml` 为准 | 对照同版本公开扩展点；可替代则迁移，不能替代则记录例外和升级测试 |
| Runtime Manifest 已将桌面对话主路径标为 Web Host，并区分旧 SDK 兼容组合 | 事实源已校正；仍不能仅凭静态检查认定全体产品插件迁移完成 | 用实际桌面 Host 探针和插件安装探针继续验收 |

聊天正文以 DSH Session 日志为持久来源；SQLite 只保存仍属于 ElecKoi 的关系型产品数据。已经废弃的模型、搜索配置和运行流水表只在版本化迁移中删除，不再有运行时读写路径。

设定工具、变量工具和请求组装通过角色 Host 插件拥有的 `eleckoiRuntimeContexts` 服务共享当前轮次数据，不再生成设定、变量或对话上下文的中转 JSON。聊天历史从官方 Session 的 `deriveMessages()` 取得，按正式消息身份处理重新生成保留的输入；关键词与 EJS 判断继续使用完整的本轮历史范围。设定目录和条件结果留在内存，变量状态替换会使条件缓存失效；设定修改成功提交数据库后才发布内存变化，变量补丁仍在本轮暂存，成功结束后按原有冲突检查提交。

每个已加载的角色 Session 只持有当前轮次，子会话按官方父会话身份共享同一状态；下一轮替换、会话释放、聊天删除和插件卸载会替换或释放对应引用。异步变量处理在提交前核对状态身份，拒绝覆盖期间发生的新修改。Agent 恢复时从产品 Repository 和正式 Session 重建临时上下文，不读取旧中转文件。Session 配置快照仅用于模型、预设和运行归属，不再保存完整设定基线、变量副本或聊天历史；正式数据库快照与官方 Session 日志的持久职责保持不变。

`session-snapshot.mjs` 在配置快照的读写边界剔除旧中转路径、设定基线和变量副本，避免模型配置刷新及子会话继承把旧大字段再次落盘。这是旧运行配置的单向字段清理，不读取旧运行正文、不修改产品数据库或 Session 日志；支持的升级来源全部不再携带这些字段后，按入口的 `RETIRE WHEN` 条件移除该清理。

启动导航由 ElecKoi 的角色聊天和创作工作室负责。共用的 `dsh-client-ui-workspace` 锁定补丁只增加 `autoSelectSession` 可选配置；官方默认仍初始化／恢复，产品组合通过官方 index-inject 的 `__DSH_UI_WORKSPACE_CONFIG__` 启动值显式关闭自动选择（Host 行配置不会传入浏览器插件），不删除原监听与归档清理。官方 `uiWorkspace` 服务、显式会话操作和引用释放保持。PC 与 Android 使用同一补丁，Android 归档直接携带该依赖，不再单独改写导航脚本；升级须分别回归默认与产品策略、归档清理、显式打开及卸载。

PC 原左侧图标导航在所有页面及侧栏收起时始终保留。插件创造所在的官方 Workspace 会话只切换图标栏右侧的二级侧栏，新会话与工作区／会话浏览由官方组件提供，主导航列表、更多及设置不重复渲染到该侧栏。Host 继续停用默认 `ui-sidebar` 自动挂载；Web Client 加载其公开 `/client` 产物，由产品壳沿公开 `apply` 与 Slots 注册合同装配，在同一个 `sidebar` 所有者下持续渲染固定导航与当前二级侧栏，保留官方注入、语言与卸载生命周期，不重复声明同名子插槽。品牌和产品入口沿公开插槽与 Client 导航接入。Android 的产品主抽屉保留原布局，工作区顶栏列表开关单独打开官方工作区浏览；两种内容沿同一 sidebar 所有者装配，工作区复用 PC 的专用会话过滤。发送前置准备按角色聊天目录中的 `runtimeSessionId` 判断归属，不拦截其他 Workspace Session。官方创造模式的技能和模板保持原样，`@eleckoi/dsh-runtime` 通过独立的官方文件技能 provider 提供 `eleckoi-plugin-development` 及由正式插件文档生成的随包参考，具体见 [从创建插件开始](plugins/create-plugin.md)。

创作工作室直接在主窗口打开，左侧工作区列表使用官方浏览器。浏览范围只在公开组件参数中投影：按角色目录的正式 runtimeSessionId、角色运行预设和正式父子关系排除角色及其后代，创作会话正常进入列表，不改写官方全局 Session 或 Workspace Controller。归属未就绪的行不先暴露；分组、未分组、平铺、搜索、打开、改名和恢复使用同一可见范围。创作会话由工作室打开，旧普通编程会话保留原入口和历史；新建只使用工作室运行预设。派生对象只含当前列表元数据，随快照替换和组件卸载释放，不缓存正文或落盘。正文检索仍按部署的官方开关执行。插件菜单保留官方两个选项，创建插件点击后立即进入工作室，在其中准备原官方草稿，不另开窗口、不发送。页面首次挂载保留正在进行或已经失败的准备状态，不重复恢复会话；准备失败沿当前工作室显示原始错误，手动重试仍可用，离开后迟到的创建结果不补写草稿或重新导航。

工作室启动预热运行预设以支持官方 Session 冷恢复；预设准备失败只记录具体异常，不能阻止工作室 Runtime 与 Remote 服务提供。列表读取会话及当前选择元数据，不校验执行预设；新建和打开仍重新准备当前预设并向调用方返回原有配置错误，修正配置后无需重启即可重试。工作区、任务、协作、联网、插件发现和创作能力的工具开关继续控制实际工具权限，关闭它们不关闭工作室列表服务，不替用户改写启停状态。

旧散列预设会话的启动转换逐条隔离失败：缺少工作室标记或读取失败时记录原异常，保留该会话和仍被它引用的生成文件，继续转换其他会话并提供服务；不猜测编辑目标或补写未知状态。无效旧生成文件的清理失败也保留原文件并记录，不阻断服务。该隔离随已有旧散列预设转换一起退役，不新增会话格式或 SQL 迁移。

共用 Runtime bundle 提供 `host-log-plugin`，沿官方 Logger exporter 回放启动缓冲并持续将原始警告／错误写入两端壳已有的 stderr 采集；不另建日志目录或跨端业务协议。启动缓冲缺口明确记录，插件卸载释放 exporter。错误原因、聚合异常及原始堆栈在本地保留，产品失败的非枚举堆栈不进入 Remote 线上字段。网关受管补丁只在错误折叠前补记录，官方支持同等诊断后连同登记与锁哈希退役，见 [错误契约](adr/0040-error-contract.md)。

创作能力的角色设定局部修改使用 `settings.edit`，仍通过原三工具发现和调用，不增加原生工具或权限入口。调用只传当前编辑角色内的条目 `id`、准确 `old_string`、字面量 `new_string`，明确替换全部时才传 `replace_all=true`；默认唯一匹配，原文为空、找不到、匹配多处或新旧相同则不写入。Host 读取最新正文完成拼接，以已有条目更新事务同步当前条目和活动版本，保留其他正文、字段、非活动版本与其他角色。成功只返回编号、替换次数和修改回执，避免模型重新输出万字正文；`settings.update` 的 `content` 继续表示完整正文。此操作编辑作者设定，沿用现有角色绑定与写入通知，不使用角色对话中的设定差异工具，无新增迁移或兼容分支。

创作工作室只注册固定的 `eleckoi-creator-active` 运行预设，内容来自产品当前全局创作预设。新旧会话都在下一轮开始时通过官方预设组合接口更新提示词、工具权限与对应会话的生成配置；已开始的工具轮次保持完整，排队的新轮次使用最新配置。全局切换不创建另一份运行配置，也不更换聊天或 Session ID。`dsh-client-creator-studio/src/host/runtime.mjs` 在启动时通过官方 Session Persistence 为旧散列预设会话追加当前预设选择，成功后移除对应生成的 `preset.json` 及空目录；打开或编辑回退到旧选择的会话时执行同一转换。原历史事件、标题与编辑目标保留，不改变数据库结构。受支持的升级、恢复、导入及历史回退来源均不会再选中旧散列预设 ID 后，按入口 `RETIRE WHEN` 注释一并移除转换、旧标识判断及目录清理；具体范围登记在 [升级代码的清理条件](DATABASE.md#升级代码的清理条件)。

生成预设的运行时声明也保留包名，由官方 profile resolver 加载；不把包名改为安装目录的 `file:` URL，否则官方插件清单无法读取包内语言资源。上传文件、剧情变量、设定库和角色计划工具的实现归 `dsh-client-roleplay/src/host`，桌面随包资源入口只转出同一实现。各工具及工作室创作能力通过各自的公开子路径导出 `locale/en.json`、`locale/zh.json`，由官方 `pluginPackages` 和插件清单提供显示信息。旧生成文件中的 `eleckoi:agent-preset/*` 只在读取时转换为当前包名，文件与 Session 历史不改写；全部受支持生成文件重新生成后删除该转换及其专用回归。

模型和推理程度由锁定 DSH 的每 Session ModelDirectory、session.selectModel 与 modelSelection 投影负责；选择会话模型时官方在后台保存新会话默认值，已有 Session 恢复自身 pending／lastUsed，不随另一个会话改默认而切换。角色准备、恢复和创作预设重组不再 select 全局模型；失效的已存路由明确报错，不自动替换成目录第一项。额外的温度、Top P、输出上限及上下文／压缩控制是产品扩展，保存为官方 Session 中可忽略的 eleckoi/model-parameters 整值事件，由 eleckoiModelParameters 投影按 Session 和提供商／模型索引，修订号检查防止覆盖并发修改，null 采用上游默认。官方日志承担持久化、订阅、继承和导入；无新数据库表或迁移。请求瀑布只读已捕获路由并应用本 Session 的控制，不改 provider、model 或 reasoningEffort；压缩阈值按实际目录容量换算比率，避免局部上下文限制放大阈值。消息回退／删除保留当前模型选择和完整参数整值，导入空白 Session 允许已有模型初始化事件。模型连接、凭据和能力声明仍归全局模型配置，聊天参数菜单只编辑本会话的生成控制，保存／取消及离开提醒保持。

角色聊天的 Session 引用由 `eleckoiConversations` 在发布已加载消息前准备完成；角色页面通过 `getSessionReference` 直接进入该就绪绑定的官方 Session 作用域，不再次等待异步打开。界面另外持有一份官方显示引用，在切换聊天及同一聊天回退、重新生成的绑定交接期间保留已有界面和输入框，待就绪绑定提交后释放旧引用；退出聊天或卸载页面也释放其引用。模型订阅在目录切到其他会话、界面尚未提交新选择的短暂阶段释放旧投影，不将条件表达式的布尔值作为会话引用读取。Host 删除当前角色或对话并清空目录选择后，页面同步清空本地选择、正文与草稿并关闭所属前端，作废未完成的打开操作；加载中和读取失败仍保留有效的当前选择。回退与重新生成保持原有聊天和 Session ID。模型重试沿正式 `model-retry` 节点的轮次、尝试编号和状态进入 AI 消息的处理过程，正文列表只保留最终失败等必要状态。

角色运行配置文件由当前产品数据与 Session 模型生成，不是可移植聊天归档的必需部分。导入首次恢复没有该文件时不安装依赖文件的运行贡献；本轮 prepare 写入配置后，原预设选择边界对同一 Agent 补齐请求、上下文和工具策略装配，以 Agent 生命周期去重，不引入另一套导入专用流程。消息回退的归属校验直接使用产品数据中的正式聊天／Session 映射。导入根会话的继承历史不等同子任务；编辑和回退按官方 seed 与格式目录重建边界并严格读回，投递回执原始归属不改，实际子任务身份保护保留。

右侧栏按官方 `AppFrame` 的归属常驻外壳，独立于主页面的键、错误边界及 Suspense；插件页与聊天往返不重建 `rightbar` 根。各 Session 的右侧栏引用、保留标签和释放继续由官方 `SidebarSessionViews` 管理，不能把右侧栏放进页面加载占位或错误回退中，也不能绕过其引用归属校验。

PC 产品页面与工作区统一在字标上方显示侧栏开关、应用、编辑，折叠时菜单转回主区 caption 并保持相同顺序。工作区挂载期间启用官方 `data-windows-titlebar`，卸载时恢复原有标记；侧栏开关以第二列绝对定位，不占用左侧图标导航，不为整列设置会重定向和裁剪官方 fixed 提示的 `contain: layout paint`。官方提示与菜单继续沿各自浮层合同呈现；“未分组”保留官方没有 backing Workspace 的固定收纳语义，不伪造可改名工作区。工作区通过已有品牌插槽省去重复图标，左侧导航仍保留品牌图标。Windows 窗口按锁定版本的 40px caption 与 `titleBarStyle: hidden`／`titleBarOverlay` 呈现原生窗口控件，不再展示网页自绘控件；既有桌面主题通道只接收受管窗口主文档的主题和颜色，窗口自身的颜色随当前页面同步，应用主题选择仍由主窗口负责。编辑器原有 `beforeunload` 未保存拦截继续生效。

原生窗口按钮的底色按明确的窗口 `view` 归属取色：角色卡管理器复用根主题中的 `--character-manager-canvas`，预设管理器复用 `--chat`，其余窗口保留 `--list`。管理器的内容画布与原生控件共用同一颜色变量，不在 Preload 再写一份深浅色值；图标仍沿当前主题前景色，主题通知去重与卸载释放保持。

节点项目容器保留为显式开发入口，后续接入位置通过源码中的 `NODE STUDIO` 注释标注。主窗口工作室保留会话标题与官方动态视图目录，视图栏容器按锁定 `ConversationRoot.module.css` 的公开呈现校准：13px／16px 文字、25px 标签、32px 间距、2px 底线和独立的 22px 更多按钮。没有引入官方私有组件或改写依赖，手机视图装配保持原样。

PC 工作区与角色聊天共用官方 Workspace 导航拥有的唯一前台 `mainView`。角色正文就绪后通过公开 `uiWorkspace.openSession` 接续该身份，自己的保留引用使用 `eleckoiRoleplayView`；产品壳按角色目录中的正式 `runtimeSessionId` 选择角色页面。不能让已离开的工作区和当前角色正文同时各持一个 `mainView`：官方 UI Session 会保持原先仍被保留的前台，导致角色页的展开按钮与右侧栏指向不同会话。此处只接续界面导航，不修改 Session 历史或 Workspace 成员。Android 沿用现有挂载方式。

角色聊天的过程弹窗复用原 Session 的官方 keyed Chat 渲染器，以 `TurnProcessSpec` 的最终正文边界区分过程与答案，再通过 Portal 放入产品 `MenuSurface`；最后正文仅在主聊天显示。最终节点的 reasoning／response 分区按官方标识分别处理，response 位置不再重绘思考；不按文本去重。节点的 Hook Context、第三方工具子 Slots、文件操作与授权图片读取保持原归属，子 Slots 使用独立命名空间避免重复声明。工具卡的「查看」关闭弹窗并透传原 Session 的 inspectCall，以原生 callId 定位官方轨迹及调用检查器；不另设 JSON 弹窗。主会话不再订阅、复制和拼接子会话正文，子会话读取只由官方顶部目录及侧栏管理。轻量单行状态仍由产品展示投影提供；聊天日志、模型请求、结束通知和子任务等待策略保持原样。

角色与创作工作室的自定义压缩模板只替换官方压缩请求末尾的摘要指令，保留官方选择的历史消息、工具声明、工具历史、输出上限和取消信号。工具声明仍用于官方请求前缀及历史工具解析；禁止以摘要不执行工具为由删除这些声明。压缩请求仍由同版本官方压缩引擎选区、调用模型、校验及提交摘要；请求失败不能视为压缩成功。

角色设定库与剧情变量的六个搜索／读取工具沿原 `ToolCallTree` 与 `tool.call.toolview` 分派产品结果视图，保留原调用身份、useDisclosure、inspect 及其他工具的 fallback。完整返回结果在当前挂载组件中派生虚拟目录和单条阅读，不新增会话、数据库或投影缓存副本；缓存设定只展示正式读取回执，不用当前配置重建历史正文。右侧直接显示正文并按动态高度虚拟化，没有第二次展开；长单行分块保留全部字符，左右滚动区直接使用官方主题皮肤。手机在同一结果区域阅读和返回，隐藏窗格保持可测量以维持虚拟范围与滚动位置。

同一分派入口另接 `eleckoi_apply_variable_patch` 与 `eleckoi_apply_setting_patch` 的可读修改视图，沿用官方 DisclosureRow、编辑图标及原始调用 inspect。变量逐项展示记录中的 JSON Pointer 路径、设置／增减／添加／删除动作和值，不推算未记录的历史旧值；设定从本次调用展示原文片段／替换文字、写入正文或移动／删除／创建路径。只依据正式返回的操作数、替换次数、未变化、校验失败和 interrupted 事实显示状态，不把业务拒绝当成功。修改详情按动态高度虚拟化并保留全部文字与操作，无总量上限；读取书本移除额外书签笔画。无法安全解析的普通结果、溢出提示、结果续读或非文字附件继续交给原生展示。此处只解释现有 Session 调用记录，不查询当前数据库来重建历史、不重做写操作，也不新增日志、投影、缓存、数据库升级或原生工具成员。

大工具结果沿用同版本官方 `spill-policy` 的 Token 预算与完整文件存储。共用 Host 在官方 `LocalSpillStore` 扩展中为每个结果保存一份小型会话归属凭据，由现有 `eleckoi_read_setting_files`、`eleckoi_read_variables` 和 `eleckoi_call_capability` 的 `result` 参数提供按 UTF-8 字节续读及文字搜索，不新增 AI 工具或独立工具组；完整正文只保存一次，不建立结果索引数据库、不在每次模型请求中追加结果副本。删除聊天时，Host 按正式 Session 日志确定本会话及被一同删除的子会话，使用官方目录编码删除它们的完整结果、归属凭据及结果目录；删除角色卡沿用其关联聊天的同一流程，独立创作工作室会话由自己的删除操作清理。清理失败向调用方报告并保留日志供重试，全部清理完成后才删除日志；继续保留官方启动时按文件年龄回收过期文件的机制，不增加清理队列或迁移。结果失效后明确要求重新查询源数据。各入口只读取本工具组在当前会话产生的结果，或正式分叉继承的同组祖先结果；普通业务参数与 result 模式互斥，续读不重复执行原操作。上传文件与本机路径统一由官方 `read`／`read_image` 读取，遵循原生文件系统和工具权限；不再使用产品上传文件读取器或其独立结果续读入口。

该存储扩展由 PC 与 Android 共用的角色 bundle 停用官方 `spill-local` 项后，以独立配置项挂载。锁定版本的 patch `name` 字段只核对目标身份，不能替换插件；直接改写该字段会导致 patch 被跳过。回归须从正式 profile 加载 bundle、运行真实工具及输出策略，再恢复原会话和预设验证续读，不能用测试手动挂载存储服务代替正式装配。

锁定的 `spill-policy` 补丁通过 `pagedTools` 对现有三个入口正式返回的 `kind: tool_result_page` 分页结果免做二次溢出，普通大结果仍按官方预算溢出；`exemptTools` 仅保留原上传文件分页读取。原生工具结果与程序式工具日志使用相同合同。默认预设停止挂载 `compaction-tool-result-pruner`，已生成预设在恢复时移除同一正式插件标识；保留官方正常摘要压缩和用户阈值。此处不能用提高截断上限或在末端重新覆盖内容代替可恢复读取。

旧 Session 缺少空系统开头时，仅在锁定版本的官方 v3 到 v4 相邻迁移中补齐；通过正式校验后发布后继，保留旧文件，删除条件见 [ADR 0026](adr/0026-legacy-session-system-head-migration.md)。单个会话失败不阻断整个桌面 Host 启动。

## 数据放在哪里

工作室子代理在正式 `agent/created` 生命周期中按父会话身份补齐缺失的工作室绑定，已有绑定不重复追加；子代理的组合、模型与权限仍由官方子代理流程管理，主工作室的全局预设重组和历史列表排除 `origin="subagent"`。角色对话标题栏通过原有 Header 子 Slots 呈现官方 `conversation.session.header.actions`，包括预设标签与子智能体目录，不再另画预设标签。角色页目录的打开动作复用官方 `openChildAside`，由官方资源与右侧栏呈现子会话，主角色聊天及其侧栏按钮保持挂载。

角色对话使用官方异步子代理流程：父 Agent 可以先结束本次执行，子代理结算后由官方投递通知；父 Agent 空闲时经 followup 开始新执行，运行中则经 steer 进入后续步骤。产品不在 `agent/turn-stopping` 增加等待，不把通知唤起的新执行关联到先前用户轮次；子会话由官方顶部目录及独立视图查看。既有输入身份投影只服务于同一 Session 重新生成，不再维护子代理名称、派发或历史参数索引。删除整个角色会话时仍沿会话编辑器停止后代并删除对应会话，避免已删除的角色任务继续写入。

编辑或删除的写入句柄关闭边界先通过公开 `drainDescendants` 停止该 Agent 管理的后代，再释放主句柄并执行操作。删除聊天按正式 Header 的 `parentSession` 递归删除主、子及更深后代的会话目录，同时清理这些 Session 的角色运行配置快照与工具结果，不影响无关会话。

联网搜索与抓取使用官方 `ctx.web` 和现有 `web_search`、`web_fetch` 工具。DeepSeek Messages、Search、Fetch 及 HTTP 抓取均沿用锁定官方提供器，只有 Tavily 保留扩展。工具弹窗通过正式插件导航打开 `web-search` 设置项，DeepSeek 密钥和参数只由官方表单及 Settings、Credentials 管理。旧扩展选择在 Loader 挂载前按精确编号退役；原有官方配置与凭据保留。完整输出补丁和退役边界见 [ADR 0039](adr/0039-deepseek-search-fetch.md)。

数据位置由它的权威所有者决定，不以“统一放数据库”为目标：

- DSH 已有正式领域使用 DSH 自己的持久化合同：模型配置使用 settings/profile，密钥使用 `ctx.credentials`，聊天正文使用 Session 日志，bundle 选择使用 profile。
- DSH 的 [`dsh-storage-sqlite`](https://github.com/deepseek-ai/deepseek-harness/blob/38a6a5c965aa99ab525161efb7cc5cf1fe62fced/packages/storage/storage-sqlite/README.zh.md) 是 Host 侧的文档型 KV 后端：每个键保存一行 JSON，配合 `ctx.storageDomain` 提供 schema 校验、持久写入和进程内变更事件。简单、独立且按键读写的新增 Host 状态应优先评估这套正式合同。
- ElecKoi 的角色关系、聊天索引等关系型产品数据，在领域迁入 DSH Host 后由 Host Repository 独占 SQLite 写入；Client 和 Electron Main 不直接写。
- 创作项目、导出文件和其他以目录为产品形态的数据保存在用户选择的文件目录；Host 只维护对应文件索引，不复制进 SQLite。
- 页面加载状态、当前选择和生成中的临时状态留在 Client 内存，除非存在明确的重启恢复需求。

同一份配置不同时写入 DSH 与 SQLite。旧 SQLite 字段只在领域迁移时转换到新的权威存储，验证成功后删除旧读写路径和废弃结构。

`dsh-storage-sqlite` 不提供跨表事务、二级索引、多段键或自动迁移。现有 ElecKoi 产品库依赖关系表、外键、排序、搜索和连续版本化迁移，因此不能机械改造成 JSON KV。保留关系型产品库是数据模型选择；它仍由 DSH Host 插件独占，并通过 Typert Remote 对 Client 提供能力。DSH Session 查询索引则继续使用官方 `dsh-session-query-sqlite`，三者各自拥有独立用途和数据库身份。

## 实施顺序

1. 建立逐功能对照：官方 owner、ElecKoi 现有 owner、数据来源、正式扩展点、升级风险和验证用例。当前清单见 [插件归属与接入清单](DSH_PLUGIN_MIGRATION.md)。
2. 校正过期的 Runtime Manifest、检查器和实施文档，让它们验证实际的 Web Host 与客户端插件组合。该项事实源已校正，后续仍需继续扩充动态验收。
3. 持续复核官方包补丁与 Agent 创建/恢复适配等高耦合点；可以使用公开扩展点时移除补丁，仍需补丁时保留精确版本校验和运行探针。
4. Main 只保留窗口、资源协议、更新与 Host 进程管理；新业务进入 DSH Host/Client，现有数据库由 `@eleckoi/dsh-product-data` 独占。
5. 以真实官方/第三方插件验收安装、启用、界面效果、停用、卸载、会话恢复和上游批次升级。当前临时插件探针已覆盖安装、中文元数据、真实角色卡编辑入口、重启、停用、启用和卸载。

当前 `pnpm check:architecture` 检查目录、进程边界，并阻止已删除的 Desktop Gateway 业务桥回流；它仍不能代替真实 Host、Session 与插件生命周期验收。旧的 [桌面架构说明](history/ARCHITECTURE.md) 和私有知识库中的《ElecKoi Desktop 架构最终总纲》仅作历史索引。
