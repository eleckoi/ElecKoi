# Agent 回复界面与最终正文稳定性

[返回公开课题目录](README.md) | [English](agent-response-experience.en.md)

**状态：公开课题，已有实验，但尚无稳定方案。**

## Agent 回复不是传统聊天气泡

传统 Chatbot 的主要界面是一问一答。Agent 在给出最终回复之前，还可能经历搜索设定、读取变量、执行工具、等待结果和处理错误等阶段。电子爱需要同时呈现两类信息：

- 面向用户的最终角色扮演正文；
- Agent 的工具调用时间线，包括正在执行、已完成、失败和等待等状态。

时间线如何展开、收起和过渡到最终正文，不是次要的显示问题。它决定用户能否理解 Agent 正在做什么、为什么需要等待，以及一次回复是否已经真正结束。

## 当前的最终正文协议

电子爱目前要求 Agent 使用 `<FINAL>...</FINAL>` 标记最终扮演正文。应用据此把工具阶段与正式回复分开，并将正文放入最终消息区域。

这一协议仍然依赖模型在正确时机输出正确标签。模型发生注意力漂移时，可能遗漏 `<FINAL>`、提前输出正文，或在工具阶段与最终阶段之间混入不应出现的内容。解析器可以容忍部分不完整的结束标签，但如果缺少关键的开始标签，应用就无法始终可靠地区分过程文字和最终正文。

## 已经尝试过的方向

### 让 Agent 自己控制请求阶段

曾尝试让 Agent 判断当前是第几次模型请求，并在它认为是最后一次请求时规整最终正文。实际效果不理想：模型容易错误判断阶段，甚至反复调用已经失去作用的操作，使请求失控并浪费 Token。该方向目前视为失败实验，不作为现行方案。

### 加入角色扮演计划

当前尝试让 Agent 维护本轮角色扮演计划，并把“输出最终正文”作为明确的最后任务。计划能提高模型遵守流程和格式的概率，但不能消除标签丢失，仍然不是可靠的协议边界。

### 使用最终回复子 Agent

一个尚未验证的设想是：主 Agent 完成检索和工具工作后，调用专门的最终回复子 Agent，由子 Agent 只负责整理角色扮演正文。这可能减少主 Agent 在工具阶段与最终写作之间的注意力冲突，但也会增加一次上下文交接、模型请求、Token 消耗和等待时间。该方向目前只是待验证假设。

## 核心问题

需要找到一种不完全依赖模型逐字遵守标签的阶段切换方式，同时保留流式正文、工具时间线和多模型兼容。最终方案还必须避免为了修复显示稳定性而显著增加 Token 消耗与回复时间。
