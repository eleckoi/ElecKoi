# 聊天记录与工具结果的长期记忆

[返回公开课题目录](README.md) | [English](conversation-history.en.md)

**状态：当前只有基础实现，长期方案尚未形成。**

## 问题

Agent 的一次工具调用可能返回大量内容，例如一份完整设定、代码文件、搜索结果或变量结构。如果把所有工具调用和结果永久放入聊天历史，之后每次模型请求都可能再次携带这些内容。

如果 Agent 在多个回合中重复读取同一文件，完整原生历史中确实会出现多份重复文件内容。聊天越长，重复内容越多，输入 Token、请求时间和上下文噪声都会继续增加。旧工具结果还可能已经过时，使模型把历史状态误当成当前事实。

但如果跨回合完全忘记工具结果，Agent 也可能忘记上次查过什么、为什么得出某个结论，并在下一回合重复检索。

即使已经剥离旧工具结果，现有的 `user/assistant` 对话数组仍会在每次模型请求中整体装入。它随着角色聊天持续增长，并会在同一 Agent 回合的多次请求中反复发送。这是当前更主要的长期 Token 压力。

## 电子爱当前怎样处理

电子爱把“执行记录”和“下一回合模型上下文”分开管理：

- 工具调用、工具结果、推理过程和执行状态可以进入 Agent 时间线，供界面展示和问题追踪；
- 当前回合内保留完整工具调用链，因为模型必须看到刚取得的结果才能继续工作；
- 每次模型请求都会重新装入已有的用户消息和最终助手正文；旧回合的工具调用与工具结果不会继续发送给模型；
- 变量和设定等当前状态由各自的数据源保存，需要时重新读取，而不是把旧工具输出当成永远正确的事实。

因此，旧回合中重复读取的文件不会在电子爱的角色聊天上下文里无限累积。不过，同一回合内如果 Agent 反复读取同一内容，这些结果仍会进入该回合后续的模型请求并增加 Token。更重要的是，持续增长的对话正文仍会被反复发送；上下文缓存只能暂时缓解这一成本，不是最终解决方案。

## 对当前策略的判断

剥离旧工具结果是合理的基础选择，但它只避免了原始工具日志继续膨胀，没有解决角色对话本身越来越长的问题。当前做法实际上仍是把已有对话全部交给模型，项目对聊天记录怎样被 Agent 更有效地利用还探索得很少。

角色扮演的长期主线应当保留用户与角色真正说过的内容，以及变量、设定库等权威状态，但不一定意味着每次请求都必须逐字发送全部历史。怎样在保真、成本和模型注意力之间取舍，目前没有答案。只保留最终对话还会丢失部分有价值的工作记忆，例如已经检查过的资料、选择某种处理方式的原因，以及无需再次执行的中间结论。

## 值得研究的方向

更可能需要的是选择性记忆，而不是“全部保留”或“全部丢弃”二选一：

- 当前回合继续保留完整工具链，保证 Agent 能完成连续操作；
- 只逐字保留近期对话，把更早的剧情整理为可更新的摘要、事件和关系记忆；
- 跨回合只保留真正影响后续剧情或决策的简短结论，不保留大段原始文件内容；
- 对已读取资料记录来源、版本或摘要，使 Agent 能判断是否需要重新读取当前内容；
- 变量与世界状态继续以结构化数据为准，不把自然语言摘要变成新的权威状态；
- 设立专门的聊天记录子 Agent，由它阅读和维护 `user/assistant` 历史，再为当前角色 Agent 选择或组织上下文；同时验证额外模型请求、摘要漂移、关键信息丢失和延迟是否会抵消收益；
- 统计同一回合和跨回合的重复读取比例，再决定是否引入去重、缓存或检索式记忆。

这些只是随着 Agent 发展可能出现的设计方向，不代表已经确定的开发方案。这里先公开抛出问题；后续研究需要同时验证叙事连贯性、信息新鲜度、Token 成本、回复速度和错误恢复，而不能只追求最短上下文。
