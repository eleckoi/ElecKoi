# 角色资产库

资产库属于明确的角色，入口位于角色编辑器的「前端」下方。图片、视频、音频、模型默认混合展示，按类别下拉筛选；作者可以建立嵌套文件夹整理开场、支线与结局，不添加素材版本。支持导入本地文件、多选、复制、重命名、移动、删除、下载与复制引用。

## 存储与引用

文件由 `@eleckoi/dsh-product-data` 的 Host Repository 管理，位于产品数据库同级的 `character-assets/`。角色目录使用角色编号的 SHA-256，文件内容以自身 SHA-256 保存；显示名称从不作为磁盘路径。一个角色内相同内容共享不可变文件，复制条目获得新引用编号；复制角色则创建独立所有者。

文件夹使用固定 UUID、父文件夹编号与显示名称，素材通过可选 `folderId` 归入文件夹；未设置表示根目录。目录中的 `folders` 省略时表示空集合。这是目录合同中的可选分组信息，不建立第二套磁盘目录或数据库迁移。移动、重命名与嵌套只写原子目录；引用编号、物理文件路径和内容摘要保持。Host 拒绝跨角色归属、悬空父级、循环与移入自身后代。删除文件夹递归处理其内容，写目录失败沿同一日志恢复实际文件。

作者点击「复制引用」得到 `asset://<资产 UUID>`，例如：

```html
<img src="asset://11111111-1111-4111-8111-111111111111">
<audio controls src="asset://22222222-2222-4222-8222-222222222222"></audio>
```

引用使用固定编号，重命名不影响它。消息正文 HTML、正则／EJS 的显示结果与独立前端项目在各自的文档装配边界，把引用解析到当前角色的 Host HTTP 资源地址。`fetch`、XHR、图片、音视频、动态 DOM 和 CSS 常用赋值也在文档内解析。复杂加载器可以显式调用 `window.ElecKoiAssetUrl(reference)`，获取当前页面所属角色的实际 URL；不能持久化这个运行期 URL。此约定由产品文档装配器实现，不是操作系统注册的全局协议，普通浏览器页面不能独立识别它。

资源由官方 WebServer 路由 `/eleckoi/character-assets/<编码角色 ID>/<资产 UUID>` 提供，GET / HEAD 支持 MIME、长度、单段 Range 与下载名称；媒体不通过目录通知反复传输。资源归属来自页面当前角色，导入后的编号保持，运行地址重算。磁盘路径、`blob:` URL 和机器端口不进入作者源码或卡包。

系统文件定位可用时，单项菜单提供「打开所在文件夹」。Client 只提交角色与资产编号，Host 校验归属和文件后交给官方 `sessionController.openWorkspacePath` 的 `reveal` 操作，定位库内实际保存的文件；不定位最初上传的源文件，不另存展示副本。实际文件名是内容摘要，显示名称仍由目录保存。Android 私有存储等不提供系统定位的 Host 不展示此入口，素材下载仍使用原保存机制。

## 前端与代码的职责

正则条目保留匹配、替换源码和运行条件；完整前端保留项目文件、入口、绑定和启用选择。消息级界面（正文 HTML 或正则生成）和独立前端项目都可以引用同一个资产库。完整前端中的 CSS、JS、图片等文件保持原相对关系。文件是资源，入口与绑定是运行配置，因此不把正则条目、模型和整个界面混成同一类上传项。

完整角色导出只生成一个包：角色文档、库素材和前端文件分别置于包内目录，不包含第二层前端 ZIP。独立导入一个前端 ZIP 时会展开成项目；单独导出前端 ZIP 则把当前角色库素材放进 `.eleckoi-assets/`，由 `.eleckoi-assets.json` 登记素材及 `folders`，导入时合并到目标角色库，再创建项目。相同编号指向不同内容、文件夹名称或父级冲突时明确失败，不能改写现有资产。同编号同内容复用现有条目；空文件夹同样携带，省略 `folders` 表示没有分组信息。

完整卡导入后默认启用其选中的独立前端；没有选择时使用首个项目。作者仍可在前端入口切回默认界面。前端是否声明整页、局部座位或其他绑定仍沿其正式清单执行。

## 上传、删除与失败恢复

上传以 1 MiB 分段传输，Host 校验角色、上传票据、准确偏移和声明大小，完整接收后才发布目录。分段不是单文件大小上限。取消、离开页面和服务关闭释放暂存；无人继续传输的票据在 30 分钟无活动后清理，异常退出后也会清理遗留上传。

重命名保留类型、内容与引用编号。复制共享同角色不可变正文；删除最后一个引用时回收实际文件。目录写入失败会恢复已移动文件；异常退出通过已提交目录判定恢复或回收。删除整个角色与角色复制也覆盖素材所有者，角色导入的文件与完整前端在角色事务失败时一并撤销，不留下可玩的半张卡。清理日志用于当前异常退出恢复，不是旧版本转换或数据库迁移。

删除仍被源码引用的资产会使该引用失效，界面在删除前说明；不按静态源码搜索擅自认定某个素材没有使用。导出自动收集全部角色库素材，以包含动态引用和未选中的开场白资源。

## 界面与平台

PC 保留原编辑器顶部留空和右侧圆角。标题旁保留搜索及网格／列表切换；下一行左侧为筛选、排序、展示尺寸，右侧只有新建文件夹与导入文件。混合目录保留加号导入卡片，菜单提供多选与移动到；列表的文件夹和文件共用同一个缩略图、名称及菜单列。文件夹采用灰色立体封面，内部素材仅从上方露出，正面不粘贴图片；鼠标悬停轻微展开，点击直接进入，不执行飞出文件的动画。手机搜索完整一行，预览底部用紧凑属性、引用和并排操作，短屏优先保留可见按钮。深浅主题、减少动态效果、返回关闭浮层和键盘焦点沿当前共用机制。

文件夹视觉组件的许可证与改动说明保留在源码 vendor 目录；完整许可证也随共用网页资源的 `licenses/react-bits-folder.txt` 分发。

浅色预览表面采用已有灰色控件底色，与白色页面区分；深色保持当前灰阶。角色卡与预设编辑器打开或复用时对齐主窗口当前尺寸与最大化状态；不在拖动窗口时持续绑定两个窗口的大小。

PC 与 Android 使用相同 Host Repository、Remote、格式解码和 Web UI；各自保存本地数据，不共用磁盘绝对路径。实际文件形式与当前内存边界见 [角色卡传输格式](CHARACTER_CARD_TRANSFER.md)。
