# SDK 兼容边界

兼容能力由 `@eleckoi/dsh-compatibility-host` 和 `@eleckoi/dsh-client-tavern-shared` 装配到同版本 DSH Host/Client。跨端调用使用生成的 `eleckoiAuthorPlugins`、`eleckoiCompatibility` Remote，不新增 Electron 私有桥。完整声明见 [Remote 参考](api-remote.md)。

## 存储

- 兼容扩展字段、世界书绑定、插件状态及界面项目索引保存在产品数据目录旁的 `author-plugins/registry.sqlite`，其中 `documents` 表不属于产品主库。
- 插件 SQL 数据库按插件身份与数据库名称隔离，界面项目文件位于 `author-plugins/frontends/`。
- SDK 对原生角色、聊天、设定库和变量的操作调用现有 Host 服务，仍会修改对应的原生数据；不会为兼容字段新增主库表或迁移。
- 原生实体与兼容扩展字段分别存储，跨库写入不构成同一个 SQLite 事务。
- 请求预览、SDK 提示词历史及世界书最近扫描结果只在本次 Host 内存中保留，不写入主库、兼容库或 Session 日志。世界书计时状态保存在独立兼容库。

## 世界书

酒馆兼容条目的 `at_depth` 插入位置统一映射到 ElecKoi 现有缓存设定区，内容仍参与模型请求，不根据深度倒数插入聊天历史，也不因指定深度拒绝正常生成。原始深度保留在兼容数据中，用于读取与导出。

插入深度与关键词扫描深度是两个字段：关键词扫描范围继续按照扫描深度执行。原生设定的固定位置和自定义位置不因此改写；经 SDK 修改激活策略的原生条目保留明确的原生位置，避免在原生与兼容流程重复注入。

## 界面与生成

默认安卓与桌面页面保持原有装配。只有用户选择带明确绑定的界面项目后，才通过扩展接口挂载对应根界面、页面或插槽。互动消息使用同源 SDK 资源，生命周期结束后释放文档运行状态。

正常生成、继续与重新生成使用现有 SessionController 和角色请求准备流程；辅助生成使用 DSH `llm.stream`。兼容层不建立另一套高层 Provider 请求组装。当前合同无法表达的高级生成参数会明确报错，不静默忽略；低层网络请求必须提供明确 endpoint。

删除角色时同时删除其关联聊天和官方 Session，原生界面与 SDK 使用同一条规则，不提供保留聊天的删除选项。

这些接入边界不代表所有第三方脚本均已通过运行验证。安卓实机、特定脚本回调和外部 Provider 行为需分别验证。
