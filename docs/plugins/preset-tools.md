# 预设工具引用

预设作者可以把插件注册的工具加入预设，保存启停选择并修改显示名称。主列表按归属分为「预设工具」和「额外工具」；内置、MCP 和插件是工具来源，用于管理窗口和工具详情。内置目录仅提供默认工具组合，插件工具从当前 Host 的正式 DSH 工具注册表读取。

「预设工具」是作者明确加入的工具，既可以由内置能力提供，也可以由作者要求安装的插件提供。「额外工具」是玩家自己的插件当前提供、但预设没有引用的工具。同一个正式调用名称只显示一份；已经被预设引用的工具归入预设工具，即使其实现来自玩家安装的插件。

插件在外层只显示名称和工具数量；点击后查看该插件的全部工具、可用状态和详情，不提供加入勾选。已有任一工具被预设引用时，该插件集中显示在预设工具区域，数量以「已加入／全部」表达；剩余未加入的工具仍在同一个插件详情里，不重复平铺。没有引用的插件显示在额外工具区域。插件身份由真实注册上下文和 Loader、Bundle 声明关联，详见 [ADR 0041](../adr/0041-tool-registration-provenance.md)。

顶部「管理预设工具」统一管理工具归属。窗口先列出「内置工具」和各插件实际名称，各来源显示已选／全部数量；右侧勾选工具纳入预设，取消勾选移出预设，已有引用也可取消。窗口直接编辑外层同一份预设草稿，主列表和数量随选择更新；不设置「取消／应用修改」，关闭、返回或 Escape 只退出窗口并保留草稿。整份预设由外层「保存」统一写入，离开时沿用未保存提醒；保存失败保留草稿以供重试。未改变归属的工具保留原有显示名称、启停和配置；缺失插件的引用同样可以移除，当前窗口保留其目录项，方便误点后重新勾选。主列表的开关只负责启停，不改变归属。搜索、管理和保存控件与正则页共用工具栏组件和样式。

额外工具无需加入预设即可遵循插件的现有策略使用；纳入预设只保存工具引用和配置，供作者分享。移出引用不会关闭或卸载插件，仍在提供的工具会回到额外工具。

插件继续通过 `ctx.tools.register(defineTool(...))` 提供实现，使用现有插件中心安装和启停。没有新增工具执行器或插件安装格式。工具名称是正式调用标识；显示名称可以修改，调用标识不随显示名称改变。不会根据工具名称的前缀猜测所属软件包。

## 作者分享与使用者导入

1. 作者安装并启用所需插件，通过「管理预设工具」选择来源和工具，关闭窗口后统一保存预设。仅安装或启用插件不会把它自动加入预设。
2. 在预设使用说明中写明插件安装来源和使用要求，然后导出 JSON 或预设 PNG。
3. 导出内容只记录预设引用的工具、显示名称和启停选择；不包含额外工具、插件代码、安装包、密钥或本机运行状态。
4. 使用者导入后，即使尚未安装对应插件，预设和工具引用也会完整保留。工具页只提醒「缺少插件或工具未加载」，导入、选用预设和聊天均不以安装插件为前提。

插件不存在、尚未启用和没有注册该工具，都会使本机无法解析该引用。当前提醒不推断具体缺少哪个包，作者的使用说明负责指引安装。可用工具继续遵循 DSH 实际注册与会话策略，缺失引用不会伪造工具声明，也不会触发安装操作。

## 可移植数据

预设文件的 `tool_configuration.plugin_tools` 保存插件工具引用。例如：

```json
{
  "id": "plugin-tool:example_roll",
  "name": "作者的骰子",
  "description": "掷骰子",
  "source": "extension",
  "members": [{ "name": "example_roll", "description": "掷骰子" }],
  "included": true,
  "enabled": true
}
```

`id` 与 `members[0].name` 精确关联，不按显示名称匹配。插件引用随当前预设、保存版本和导出导入保存；运行时的 `available` 和 `extraToolGroups` 只用于界面，不写入导出文件和产品存储。关闭预设工具会保存停用选择；从预设移除插件工具会删除该引用，仍由玩家插件提供的工具回到额外工具。缺少工具不构成聊天错误。额外工具继续遵循其既有 DSH 注册策略，读取工具目录或编辑预设不会改写插件的全局启停状态。

自动配图不属于 AI 工具。`@eleckoi/dsh-auto-illustration` 在插件页独立配置，预设通过 `autoIllustration` 保存其公开选择，不占用工具名额，也不注册名为 `generate_image` 的工具。详见[角色自动配图](auto-illustration.md)。
