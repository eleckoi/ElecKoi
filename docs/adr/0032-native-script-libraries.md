# ADR 0032：原生脚本库与作者 SDK

状态：已实施。

## 背景

脚本源码、脚本设置、聊天变量和角色设定具有不同的数据归属与生命周期。作者功能需要独立的开发合同，不应依赖外部格式的运行环境，也不能把脚本源码当成提示词或设定保存。

## 决定

原生作者能力由锁定版本 DSH 的 Host、Client 插件与 Typert Remote 提供。产品数据归 product-data，Client 通过生成的 Remote 操作；不增加 Main 业务、Preload API 或私有 IPC。

### 数据与入口

| 对象 | 保存位置 | 归属与行为 |
| --- | --- | --- |
| 脚本源码及资源 | `author-scripts` 文件目录 | 使用作用域、所有者和稳定脚本编号定位，支持相对模块导入及外部编辑 |
| 脚本管理记录 | 产品数据库 | 仅保存文件引用、分组、设置、按钮定义、启停与修改标识，不保存源码正文 |
| 角色前端项目 | `author-frontends` 文件目录及产品管理记录 | 角色配置管理导入、入口选择和启用；删除角色时一并清理 |
| 当前变量与历史变量 | 原生变量领域 | 使用同一份业务状态及消息快照，不建立第二套当前变量 |
| 角色设定与预设条目 | 原生角色、设定库及预设领域 | 作者 SDK 修改原稿，模型工具产生的聊天差异仍沿现有规则处理 |

脚本库具有三个明确作用域：全局、角色和预设。全局库在各角色共享显示，不复制；角色库与角色关联，预设库与当前明确选用的预设关联。角色与预设删除分别清理所属源码和管理记录。作用域不代表多个 Client 自动共享一个执行实例。

管理入口位于角色配置。运行按钮位于现有聊天操作菜单的“脚本”项，作者设置页面以弹窗打开。脚本编号与按钮固定编号共同决定身份，不按名称或列表顺序匹配。

文件和管理记录在同一产品操作中提交，失败恢复仍有效的文件。角色卡与预设转移携带所属脚本目录的模块及资源，导入关联新所有者且保持库停用；全局库不随角色导出。产品已有数据库快照不被扩展为文件备份合同。

### 运行合同

原生脚本明确声明 `runtime.kind = eleckoi-module` 和 `runtime.apiVersion = 1`。HTML 消息通过 `head` 中唯一的 `eleckoi-author-api` meta 元素声明版本，并等待 `ElecKoiReady`；未知版本与重复声明应提供可诊断错误，不根据源码外观改写作者程序。

SDK 与原生运行服务不反向依赖兼容包。脚本在受管 Web Client 中按完整身份和代码版本启动，停止时取消候选与 SDK，等待作者清理后移除页面。相对 import 由浏览器按真实文件位置解析，源码目录的内容版本决定重载，不改写作者源码。

按钮与弹窗固定所属聊天和程序版本。聊天切换、脚本停用或源码替换后撤回旧实例，新聊天正常启动自己的程序；旧实例不能修改新聊天。错误在对应入口显示，用户可修正后重试。

「已启用」表示保存的开关状态。独立编辑窗口没有当前聊天执行实例时显示该状态，不推断主聊天窗口是否运行。当前聊天只在脚本启动且 Host 确认同一目录的规则通道后显示「运行中」；等待连接显示「启动中」，运行环境失败优先显示错误。

规则通道和消息变更订阅沿官方 `remote.$stream` 管理连接代际。规则流重连只重建通道，不重放变量修改或重新执行作者启动函数；每代重新核对 Host 的目录确认。断开代中的候选全部取消，异步完成不能回传到替换通道。整体 Connection 重置、源码或聊天变化仍沿原生命周期重建脚本，作者代码错误与正常流提前结束仍明确失败。

消息网页、正则 EJS 生成的原生网页、前端项目及脚本面板通过作者 SDK 的 `scripts.request` 调用当前聊天内明确脚本的自定义操作。运行脚本用 `scripts.registerHandler` 登记处理函数；`scripts.list` 返回完整 `scope + ownerId + scriptId` 身份和操作名，不按名称或顺序路由。相同操作在同一脚本内只能有一个处理函数，撤回后可重新登记。

此通信由现有 Client 作者运行服务管理，仅在同一客户端当前聊天和脚本运行代内传递 JSON 请求与结果；不跨 Host 搬运回调，不建立新 IPC、全局事件总线、数据库或持久消息队列。业务操作继续经现有 Typert Remote 到达 Host。请求携带运行服务确定的页面、消息或脚本来源；未就绪、目标未运行、未登记操作、作者错误与非法 JSON 均明确拒绝，不自动重试。页面关闭、聊天切换、操作撤回、脚本替换或停用会取消等待及本次操作 API；异步处理使用独立调用 API，不混入正在等待的变量候选。已经由 Host 接受的业务操作不会因调用方随后关闭而自动回滚。

### 变量与作者规则

Agent 变量工具、SDK 与作者规则使用同一份原生变量状态及处理链。一次修改依次等待 before、after、Zod 和 afterSchema 处理，成功后只保存一次；规则内部操作同一候选，不触发第二次提交。错误返回调用方，Agent 可以根据原因修正并重试。

启用脚本不构成变量修改的前置条件。没有当前聊天的实时脚本连接时，Agent 工具、表单及 SDK 直接走原变量修改与 Host 配置校验，不读取脚本目录、不要求打开聊天或等待脚本启动，也不增加规则类别、登记标记或另一个协议。已有实时连接时保留原处理回调；未运行的脚本不会执行其回调。必须由 Host 持续执行的结构、范围和同步派生计算仍属于变量配置的 Schema，不以界面脚本的在线状态代替配置。

候选固定本次规则、源码与设置版本。处理中规则或上下文变化会取消该候选，不覆盖后来保存的数据。脚本设置不等于聊天变量，设置修改独立保存，不因变量校验失败而回滚。

MVU 变量导入转换到原生变量配置，保留明确注册的 Schema、默认值、preprocess、transform 与开场白的变量版本关联。此转换不启动外部脚本库，不重复解析正文结算变量，不改变现有请求组装规则。

### 前端与原稿操作

输入框读取、填写与发送绑定官方会话输入服务；直接发送使用正式聊天流程，不改写输入框草稿。作者页面可以按明确编号切换开场白、读取和修改变量、辅助计算、直接发送用户消息并生成，以及读取生成和消息变更事件。

设定库与预设条目接口修改原稿及其当前版本。批量开关、正文与条目顺序使用正式产品操作，不把模型工具的聊天差异误当成原稿，也不新增另一套聊天差异写入入口。

## 验收边界

- 原生 SDK、三类脚本、作者规则和前端交互在不装配兼容运行器的实际 Host、Client 与 Electron 应用中独立工作。
- 错误、重试、异步完成、聊天切换、停用和所属对象删除都覆盖真实调用链，测试仅使用合成资料。
- 数据转移保留原生条目编号及明确关联，失败不损坏现有产品数据。
- 普通文件下载等未接通能力不因管理 Remote 存在而宣称已开放。
