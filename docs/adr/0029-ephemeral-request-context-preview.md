# ADR 0029：运行期间查看实际请求，停止请求副本写入放大

## 状态

已采纳，2026-10-07。

## 已确认的问题

角色扩展原先在每次模型请求时向 Session 追加 `eleckoi/request-context`，保存完整可读输入。随着历史增长，重复保存形成写入放大：每轮新增相近长度的消息时，累计全文副本按平方增长。原投影还保留所有请求全文，通过投影缓存、Session 列表和连接基线传输，没有请求数量或字节上限。读取侧限制不能停止磁盘写入。

产品目录的 `list()` 原先还逐行调用 `sessionController.inspect()`，仅为一小段预览而物化整份事件。官方查询可以复用观察缓存，不能据此声称每次都重新读盘；缓存缺失时的全日志加载和逐行检查已确认。用户报告的具体大文件容量不是本次本地测量结果。

用户最终选择即时排查：只查看本次运行真正发送的请求，退出客户端后不恢复；不提供历史请求还原，也不根据后来编辑的设定或消息推算之前发出的内容。入口位于输入菜单的变量查看器上方，大弹窗左侧列轮次和请求，右侧复用原有上下文的可读排版。

## 官方基准

锁定 DSH `0.2.0-rc.2`、提交 `c1b47e41fcd54d20a0f061df28683bfc29ee24e5`：

- [Session surface](https://github.com/deepseek-ai/deepseek-harness/blob/c1b47e41fcd54d20a0f061df28683bfc29ee24e5/packages/core/session/src/surface.ts) 处理消息替换、压缩及注册的纯投影。
- [请求不变量](https://github.com/deepseek-ai/deepseek-harness/blob/c1b47e41fcd54d20a0f061df28683bfc29ee24e5/packages/core/agent-loop/src/invariant.ts) 核对官方循环派生的请求。
- [Remote stream](https://github.com/deepseek-ai/deepseek-harness/blob/c1b47e41fcd54d20a0f061df28683bfc29ee24e5/packages/api/gateway/src/client/remote-stream.ts) 提供 Client 单消费者的取消和连接恢复生命周期。
- [官方目录](https://github.com/deepseek-ai/deepseek-harness/blob/c1b47e41fcd54d20a0f061df28683bfc29ee24e5/packages/api/session-controller/src/list.ts) 使用 Header 和已有投影缓存，无需激活全部会话。

产品在官方消息表面基础上装配插入点、角色历史筛选、正则后的输入与补充指令。预览必须捕获这条真实发送链上的消息，不能用原生日志派生结果或当前配置冒充最终产品请求。

## 决定

1. 删除额外全文写入、请求输入引用和变换事件、设定投影信封写入，以及用于预览的 Session 投影。官方聊天、工具调用、工具结果、请求统计和轨迹继续按正常机制保存。预览不写 Session 日志、SQLite、检查点、浏览器存储或单独文件。
2. Host 在产品 `llm/stream` 装配完成、交给官方 LLM Runtime 的位置捕获实际请求。仅捕获正式根 Agent 的聊天请求，不为打开弹窗生成请求或重建旧请求。角色配置文件仍承担已有的当前运行装配职责，不承担预览历史存储。
3. 每个请求保留不可变消息版本的引用数组。依据正式消息 ID 及内容相等性共用未变化的消息和设定计划；编辑或配置变化形成新的版本，不能改写已捕获的请求。内存中不提前生成各请求的可读全文副本。关闭 Host、移除插件或删除聊天时释放对应数据。
4. 左侧目录只通过生成的 Typert Remote stream 传输轮次、请求编号、模型与正式步骤身份。轮次以 Session 的真实用户输入身份确定，同一输入重新生成仍属同一聊天轮次。慢消费者合并目录通知，不排队保存请求正文。
5. 右侧通过一元 Remote 按运行期请求 ID 读取，选择后才临时生成可读内容。Client 只保留当前选中的正文；切换请求或关闭弹窗取消读取，迟到结果不能覆盖当前请求。编号、角色、标题、来源、真实顺序、长文本折叠和展开沿用现有组件与主题样式。
6. 从轨迹详情移除历史上下文查看入口。当前运行捕获的请求可以在弹窗反复查看；重启后目录为空，不读取日志来恢复预览。旧全文事件保留，以免破坏仍有效的 Session 恢复和导入。退役缓存 `eleckoiRequestContexts`、`eleckoiRequestInput` 通过官方缓存 schema 与 Storage Domain 的原子更新删除，其他投影及缓存身份保留。
7. 产品目录一次调用官方 `sessionController.list()`，使用最多 240 个 Unicode 码点的 `eleckoiConversationPreview`。无缓存的旧会话先显示现有开场预览，首次打开后正常折叠。目录不得为了补齐预览逐个扫描正文。

2026-11-08 补充：常驻系统指令改在官方提示词组装阶段置于首位，沿用官方 `system/message` 版本记录，供轨迹显示初始与更新后的系统提示词；不再只在发送阶段追加。这些正式系统提示词事件与运行期完整请求预览是不同的数据职责，不增加逐请求全文事件或预览持久化。预览当前配置时重新组装系统提示词，避免历史系统头重复包含常驻正文。

## 验收与长期约束

- 真实官方 AgentLoop 发送给合成适配器的消息与当前运行预览一致；覆盖设定变化、编辑历史、同 Session 重新生成、删除和独立磁盘重开。新 Host 不恢复任何请求预览。
- 100 轮、每轮 7 次请求，大型合成设定、聊天和工具结果不产生额外请求事件或设定信封；目录不包含正文，预览保持设定位于本轮输入前的顺序，并完整展示当前轮的工具流程。
- 切换请求、取消、错误重试、连接生命周期、不同会话隔离与 Host 释放均有回归检查。聊天列表不调用逐行 `inspect()`；缓存退休可重复执行并保留其他数据。
- 新增任何日志、快照、投影、缓存或列表字段前，核对每轮新增字节、累计历史复制次数、缓存释放时机、实际传输范围。不得把“读取有上限”当作“写入不会放大”。

本次不改变产品 SQLite 版本。停止新写入不会自动缩小原有大日志；不得为缩小体积擅自删除用户已有的有效历史。
